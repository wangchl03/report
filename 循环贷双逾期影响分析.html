循环贷双逾期影响分析

聚焦场景：首贷 s8 → 还款过半获循环贷资格 → 第2笔循环贷 s8 → 两笔全逾期

一、场景定义：什么是"双逾期"

发生了什么事：
用户首贷放款 → 还款 ≥ 50% → 系统开通循环贷 → 用户借第2笔 → 首贷停还 → s8 → 第2笔连带 → s8

如果不开循环贷：用户首贷 s8 后，没有第 2 笔可借——只损失 1 笔。开了循环贷：1 个劣质用户产生 2 笔坏账。

指标口径说明

首贷 / 第2笔
用户维度按 apply_time 升序编号，seq=1 为首贷，seq=2 为第2笔放款
ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY apply_time)
循环贷订单
在上一笔订单还款≥50%且未结清（在途状态）时支用的贷款。数据源：side_recycle_type_copy，recycle_type=2。注：首贷永远不是循环贷，最早从第2笔开始出现
LEFT JOIN side_recycle_type_copy WHERE recycle_type = 2
非循环贷订单
用户在无在途订单（全部结清）后申请的贷款，每次独立审批；或 recycle_type=3 / 无标签
recycle_type != 2
s8（坏账）
loan_status_code = 8，即该订单最终结清状态为"坏账/核销"，视作终态损失
loan_status_code = 8
回款率
s8 订单中，实际回收款占放款金额的比例。回款率越高说明催收效果越好
s8_repaid / s8_remit × 100%
双逾期
同一个用户的第1笔和第2笔放款均终态为 s8。循环贷场景下：首贷还款过半→获资格→第2笔→两笔全坏账
seq=1 AND seq=2 均为 loan_status_code=8
双正常
同一个用户的第1笔和第2笔放款均正常结清（loan_status_code=7）。本次分析排除 status=5（在途）的用户
seq=1 AND seq=2 均 loan_status_code = 7
净损失
放款金额 - 还款金额（终态订单）。正值=亏损，负值（即还款>放款）=盈利
SUM(end_remit) - SUM(end_repaid)
额外损失
仅指循环贷双逾期场景下第2笔的净损失。若不开循环贷这笔放款不会发生
第2笔 s8 的 (remit_amt - repaid_amt)
循环贷双逾期率
有第2笔放款的循环贷用户中，首贷和第2笔均 s8 的用户占比
双s8-循环贷人数 / 有第2笔的循环贷总人数 × 100%
盈利率
终态订单的 (还款金额 - 放款金额) / 放款金额。正值=盈利，负值=亏损
(end_repaid - end_remit) / end_remit × 100%
终态订单
loan_status_code IN (7,8) 的订单，排除了 status=5（在途未结清订单）
WHERE loan_status_code IN (7,8)
等放用户
注册以来从未被拒绝过（is_remit=0）的用户，首次提单即放款
MIN(is_remit=0 的 apply_time) IS NULL
原生非等放用户
首次提单被拒绝（is_remit=0），后来才首次获批放款（is_remit=1）的用户
MIN(is_remit=0 时间) < MIN(is_remit=1 时间)

四、循环贷多笔连带逾期：第2笔+第3笔均为循环贷

与前期分析的"第1笔+第2笔双逾期"不同，本部分聚焦于第2笔和第3笔均为循环贷订单的用户。这类用户已经通过循环贷体系支用了两次，如果两笔都逾期（s8），说明循环贷的筛选机制在"多轮支用"场景下存在加速崩盘的风险。

更关键的是回款率的陡降：第2笔 s8 回款率还有 78.5%（用户借第2笔时尚有还款意愿），但第3笔 s8 回款率骤降至 30.2%。

这说明循环贷的劣化是加速而非线性的：用户在借第2笔循环贷时还能回收 78.5%，借了第3笔后全面崩盘。这是一个强烈的信号——当一个用户在首笔循环贷（第2笔）就出现逾期时，立即冻结后续循环贷资格可以避免第3笔几乎全额坏账的损失。
Trade-off 量化（三笔维度）：等放双正常用户 8,471 人盈利 +3972 万，双逾期 4,792 人损失 -994 万。盈利是损失的 4.0 倍，与"第1+第2笔"的 3.0 倍持平。

但注意：29.8% 的用户产生了几乎与那 52.7% 用户相当的亏损。如果能识别出即将崩盘的 4,792 人，等放循环贷的总盈利可以从 +2978 万 提升到 +3972 万，提升 994 万。

五、结论与建议

问题本质：循环贷双逾期是"透支逃逸"的典型表现。用户在首贷还款已出现困难信号后，利用循环贷资格"再借一笔"，导致 1 个劣质用户产生 2 笔坏账。等放中 18.5% 的循环贷用户属于这类场景，造成 1344 万 额外损失。
机会：双逾期用户的首贷回款率仍高达 89.2%（等放），说明在获得循环贷资格的时点（还款 ≥ 50%），用户的行为数据尚未完全暴露风险。如果能在此时间窗口内识别出"还款动机正在衰减"的信号，就可以在用户崩盘前关闭循环贷资格，避免第 2 笔的损失。
建议策略：
1. 动态评分卡——在循环贷资格开通时，不仅看"已还款 50%"，还加入还款时间间隔、还款金额波动、是否临近还款日等 还款质量指标
2. 阶梯额度——对首次获得循环贷资格的用户，第 2 笔额度控制为首贷的 50%~70%，降低单笔损失上限
3. 冷静期——首次获得循环贷资格后，设置 3~7 天冷静期再开放支用，过滤"冲动透支"行为
4. 反比控制——等放循环贷双逾期率 18.5% 是明显的红线。建议将双逾期率控制在 10% 以下作为风控 KPI
底线判断：循环贷在等放中整体仍是正向的（双正常用户利润是双逾期损失的 3 倍）。不建议因噎废食关闭循环贷，但 18.5% 的双逾期率说明筛选精度有显著提升空间。如果能把双逾期率从 18.5% 降到 10%，等放每年可多留存约 618 万 利润（按线性估算约 620 万）。

附录：完整 PGSQL 查询代码

-- ============================================================================
-- 循环贷双逾期影响分析 -- 完整 PGSQL 查询
-- 数据源: wangchuanliang.order_loan_f_v2_copy (订单主表)
--         wangchuanliang.side_recycle_type_copy (循环贷标签)
-- 范围: 2025.01 ~ 2026.05 注册用户, 全量
-- 口径: 双正常 = 第1笔和第2笔均 loan_status_code=7，排除任一笔为5(在途)的用户
-- ============================================================================

WITH user_type AS (
    SELECT user_id,
        CASE 
            WHEN MIN(CASE WHEN is_remit = 0 THEN apply_time END) IS NULL THEN '等放'
            WHEN MIN(CASE WHEN is_remit = 1 THEN apply_time END)
               < MIN(CASE WHEN is_remit = 0 THEN apply_time END) THEN '迁移'
            ELSE '原生非等放'
        END AS utype
    FROM wangchuanliang.order_loan_f_v2_copy
    WHERE reg_date >= '2025-01-01' AND reg_date <= '2026-05-31'
    GROUP BY user_id
    HAVING SUM(CASE WHEN is_remit = 1 THEN 1 ELSE 0 END) > 0
),
loan_seq AS (
    SELECT 
        o.user_id, ut.utype,
        o.serial_id, o.remit_amt, o.repaid_amt, 
        o.loan_status_code, o.overdue_days, o.loan_day, o.apply_time,
        ROW_NUMBER() OVER (PARTITION BY o.user_id ORDER BY o.apply_time) AS seq
    FROM wangchuanliang.order_loan_f_v2_copy o
    JOIN user_type ut ON o.user_id = ut.user_id
    WHERE o.is_remit = 1
      AND o.reg_date >= '2025-01-01' AND o.reg_date <= '2026-05-31'
),
recycle_tag AS (
    SELECT serial_id, recycle_type
    FROM wangchuanliang.side_recycle_type_copy
    WHERE recycle_type IN (2, 3)
),
loan2_tag AS (
    SELECT ls.user_id, ls.utype, ls.seq, ls.serial_id,
        ls.remit_amt, ls.repaid_amt, ls.loan_status_code, ls.overdue_days,
        COALESCE(rt.recycle_type, 0) AS cycle_type
    FROM loan_seq ls
    LEFT JOIN recycle_tag rt ON ls.serial_id = rt.serial_id
    WHERE ls.seq <= 2
),
-- 第1笔和第2笔配对, 排除任一笔为 status=5(在途) 的用户
pair AS (
    SELECT 
        l1.user_id, l1.utype,
        l1.loan_status_code AS s1_status, l1.remit_amt AS s1_remit, l1.repaid_amt AS s1_repaid,
        l2.loan_status_code AS s2_status, l2.remit_amt AS s2_remit, l2.repaid_amt AS s2_repaid,
        l2.cycle_type
    FROM loan2_tag l1
    JOIN loan2_tag l2 ON l1.user_id = l2.user_id AND l2.seq = 2
    WHERE l1.seq = 1
      AND l1.loan_status_code != 5
      AND l2.loan_status_code != 5
)
-- 按用户类型和场景聚合
SELECT 
    utype                                                              AS "用户类型",
    CASE 
        WHEN cycle_type = 2 AND s1_status = 8 AND s2_status = 8 
            THEN '双s8-循环贷'
        WHEN cycle_type = 2 AND s1_status = 8 AND s2_status != 8 
            THEN '首贷s8-循环贷(第2笔正常)'
        WHEN cycle_type = 2 AND s1_status != 8 AND s2_status = 8 
            THEN '循环贷s8-首贷正常'
        WHEN cycle_type = 2 AND s1_status = 7 AND s2_status = 7 
            THEN '双正常-循环贷'
        WHEN cycle_type != 2 AND s1_status = 8 AND s2_status = 8 
            THEN '双s8-非循环贷'
        WHEN cycle_type != 2 AND s1_status = 8 AND s2_status != 8 
            THEN '首贷s8-非循环贷'
        ELSE '其他'
    END                                                                 AS "场景",
    COUNT(*)                                                            AS "用户数",
    SUM(s1_remit)                                                       AS "首贷放款",
    SUM(s1_repaid)                                                      AS "首贷还款",
    SUM(s2_remit)                                                       AS "第2笔放款",
    SUM(s2_repaid)                                                      AS "第2笔还款",
    SUM(CASE WHEN s1_status = 8 THEN s1_remit ELSE 0 END)              AS "首贷s8放款",
    SUM(CASE WHEN s1_status = 8 THEN s1_repaid ELSE 0 END)             AS "首贷s8还款",
    SUM(CASE WHEN s2_status = 8 THEN s2_remit ELSE 0 END)              AS "第2笔s8放款",
    SUM(CASE WHEN s2_status = 8 THEN s2_repaid ELSE 0 END)             AS "第2笔s8还款",
    (SUM(s1_repaid) + SUM(s2_repaid)) - (SUM(s1_remit) + SUM(s2_remit)) 
                                                                        AS "总利润"
FROM pair
GROUP BY utype, scenario
ORDER BY utype, scenario;


-- ============================================================================
-- 补充查询: 第2笔+第3笔均为循环贷 双逾期分析
-- 聚焦第2笔和第3笔都是循环贷订单(recycle_type=2)的用户
-- 分析两笔都s8的场景与两笔都s7的场景对比
-- ============================================================================

WITH user_type AS (
    SELECT user_id,
        CASE 
            WHEN MIN(CASE WHEN is_remit = 0 THEN apply_time END) IS NULL THEN '等放'
            WHEN MIN(CASE WHEN is_remit = 1 THEN apply_time END)
               < MIN(CASE WHEN is_remit = 0 THEN apply_time END) THEN '迁移'
            ELSE '原生非等放'
        END AS utype
    FROM wangchuanliang.order_loan_f_v2_copy
    WHERE reg_date >= '2025-01-01' AND reg_date <= '2026-05-31'
    GROUP BY user_id
    HAVING SUM(CASE WHEN is_remit = 1 THEN 1 ELSE 0 END) >= 3
),
loan_seq AS (
    SELECT 
        o.user_id, ut.utype,
        o.serial_id, o.remit_amt, o.repaid_amt, 
        o.loan_status_code, o.overdue_days,
        ROW_NUMBER() OVER (PARTITION BY o.user_id ORDER BY o.apply_time) AS seq
    FROM wangchuanliang.order_loan_f_v2_copy o
    JOIN user_type ut ON o.user_id = ut.user_id
    WHERE o.is_remit = 1
      AND o.reg_date >= '2025-01-01' AND o.reg_date <= '2026-05-31'
),
recycle_tag AS (
    SELECT serial_id, recycle_type
    FROM wangchuanliang.side_recycle_type_copy
    WHERE recycle_type IN (2, 3)
),
loan_tag AS (
    SELECT ls.user_id, ls.utype, ls.seq, ls.serial_id,
        ls.remit_amt, ls.repaid_amt, ls.loan_status_code, ls.overdue_days,
        COALESCE(rt.recycle_type, 0) AS cycle_type
    FROM loan_seq ls
    LEFT JOIN recycle_tag rt ON ls.serial_id = rt.serial_id
    WHERE ls.seq IN (1, 2, 3)
),
-- 三笔配对, 要求第2笔和第3笔均为循环贷
triple AS (
    SELECT 
        l1.user_id, l1.utype,
        l1.loan_status_code AS s1_status, l1.remit_amt AS s1_remit, l1.repaid_amt AS s1_repaid,
        l2.loan_status_code AS s2_status, l2.remit_amt AS s2_remit, l2.repaid_amt AS s2_repaid,
        l3.loan_status_code AS s3_status, l3.remit_amt AS s3_remit, l3.repaid_amt AS s3_repaid
    FROM loan_tag l1
    JOIN loan_tag l2 ON l1.user_id = l2.user_id AND l2.seq = 2 AND l2.cycle_type = 2
    JOIN loan_tag l3 ON l1.user_id = l3.user_id AND l3.seq = 3 AND l3.cycle_type = 2
    WHERE l1.seq = 1
      AND l2.loan_status_code != 5      -- 排除在途
      AND l3.loan_status_code != 5      -- 排除在途
)
SELECT 
    utype                                                              AS "用户类型",
    CASE 
        WHEN s2_status = 8 AND s3_status = 8 THEN '第2第3均s8'
        WHEN s2_status = 8 AND s3_status != 8 THEN '第2s8-第3正常'
        WHEN s2_status != 8 AND s3_status = 8 THEN '第2正常-第3s8'
        WHEN s2_status = 7 AND s3_status = 7 THEN '第2第3均s7(双正常)'
        ELSE '其他'
    END                                                                 AS "场景",
    COUNT(*)                                                            AS "用户数",
    SUM(s1_remit)                                                       AS "首贷放款",
    SUM(s1_repaid)                                                      AS "首贷还款",
    SUM(s2_remit)                                                       AS "第2笔放款",
    SUM(s2_repaid)                                                      AS "第2笔还款",
    SUM(s3_remit)                                                       AS "第3笔放款",
    SUM(s3_repaid)                                                      AS "第3笔还款",
    SUM(CASE WHEN s2_status = 8 THEN s2_remit ELSE 0 END)              AS "第2笔s8放款",
    SUM(CASE WHEN s2_status = 8 THEN s2_repaid ELSE 0 END)             AS "第2笔s8还款",
    SUM(CASE WHEN s3_status = 8 THEN s3_remit ELSE 0 END)              AS "第3笔s8放款",
    SUM(CASE WHEN s3_status = 8 THEN s3_repaid ELSE 0 END)             AS "第3笔s8还款",
    (SUM(s1_repaid) + SUM(s2_repaid) + SUM(s3_repaid)) 
    - (SUM(s1_remit) + SUM(s2_remit) + SUM(s3_remit))                  AS "总利润"
FROM triple
GROUP BY utype, scenario
ORDER BY utype, scenario;
