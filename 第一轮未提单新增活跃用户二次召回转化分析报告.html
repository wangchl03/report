二次召回转化分析报告

聚焦第一轮减息券触达后未提单、但重新活跃的用户，评估二次触达的转化效率。

第一轮观察期：2026-08-18 至 2026-08-29
第二轮提单观测期：2026-08-27 至 2026-08-29
报告生成时间：2026-08-31

一、分析背景与策略逻辑

原有方式是对流失用户发放 7 天减息券；7 天后，未提单用户再次获得触达。问题在于：第一轮已经触达、仍未提单且后续没有活跃动作的用户，实际提单意愿通常很低，重复触达会拉低营销产出。

旧策略
第一轮未提单用户，统一进入第二轮触达。
新策略
第一轮未提单用户中，仅保留后续重新活跃的用户进行第二轮触达；未活跃用户不再触达。
本报告要验证的问题：被“新增活跃”筛出的二次触达用户，是否能在较短时间内产生与第一轮相当的提单转化，从而证明把资源集中在重新活跃用户上是有效的。

二、样本与统计口径

样本为 t7recall_active0827 与 t7recalllist_0818_0819 按 churn_user_id 内连接后的用户。先按用户去重；提单指用户在 2026-08-27 00:00:00 至 2026-08-29 23:59:59 期间存在 apply_time 的订单；提单率 = 有至少一笔提单的去重用户数 ÷ 内连接去重用户数。

六、综合判断与后续动作

策略有效的依据
第一轮已验证：被过滤用户占 5,328 人，但仅产生 36 位提单用户，提单率 0.68%。二次触达仅面向重新活跃用户后，1,071 人在 3 天内即达到 11.30% 提单率，说明“先用活跃行为筛选、再触达”的方向能够减少低效覆盖，并快速承接有意愿用户。
解读边界
二次触达用户是经过“重新活跃”筛选的人群，与第一轮全量用户并非随机同质样本。因此，本报告可以说明该筛选方法有较高的运营效率和转化速度；若需估计二次券触达本身的因果增量，仍应在新增活跃人群内保留随机对照组。

建议动作

  1. 将“第一轮未提单 + 新增活跃”固定为第二轮触达的准入条件，不再对未活跃用户进行普遍二次发券。
  2. 把触达后 0–3 天作为核心观察窗口，按日监控提单率、券使用率和取消/拒绝等漏斗指标。
  3. 对样本量较大的 20d、20d+10r、30d 分层设置独立的券力度或触达频次测试，避免将小样本分层结论直接放大。
  4. 在新增活跃用户中设置随机对照组，进一步区分“用户自然恢复意愿”与“二次触达带来的额外转化”。

以下代码覆盖报告全部数值：模块一读取已发布的第一轮导出汇总值，模块二从数据库内连接样本并计算二次触达的样本规模、日期趋势及分层指标。

模块一：第一轮策略报告的导出数据对比值
/* 第一轮策略报告的已发布导出结果；用于复现本报告的对比卡片。 */
WITH first_round_source AS (
    SELECT * FROM (
        VALUES
            ('第一轮新策略整体', 11585::bigint, 1342::bigint),
            ('被新策略过滤用户', 5328::bigint, 36::bigint)
    ) AS t(metric, sample_users, apply_users)
)
SELECT
    metric,
    sample_users,
    apply_users,
    ROUND(apply_users::numeric / sample_users * 100, 2) AS apply_rate_pct
FROM first_round_source
ORDER BY metric;
模块二：样本内连接、总体提单率、日期趋势与分层指标
WITH active AS (
    SELECT
        churn_user_id::bigint AS user_id,
        MAX(strat_1) AS strat_1
    FROM wangchuanliang.t7recall_active0827
    GROUP BY churn_user_id::bigint
),
recall_list AS (
    SELECT DISTINCT churn_user_id::bigint AS user_id
    FROM wangchuanliang.t7recalllist_0818_0819
),
sample AS (
    SELECT a.user_id, a.strat_1
    FROM active AS a
    INNER JOIN recall_list AS r
        ON r.user_id = a.user_id
),
apply_orders AS (
    SELECT
        s.user_id,
        s.strat_1,
        o.serial_id,
        o.apply_time,
        o.apply_date,
        ROW_NUMBER() OVER (
            PARTITION BY s.user_id
            ORDER BY o.apply_time, o.serial_id
        ) AS first_apply_rn
    FROM sample AS s
    INNER JOIN wangchuanliang.order_loan_f_v2_copy AS o
        ON o.user_id = s.user_id
    WHERE o.apply_time >= TIMESTAMP '2026-08-27 00:00:00'
      AND o.apply_time < TIMESTAMP '2026-08-30 00:00:00'
)
SELECT
    (SELECT COUNT(*) FROM active) AS active_users,
    (SELECT COUNT(*) FROM recall_list) AS recall_list_users,
    (SELECT COUNT(*) FROM sample) AS joined_users,
    (SELECT COUNT(DISTINCT user_id) FROM apply_orders) AS apply_users,
    (SELECT COUNT(*) FROM apply_orders) AS apply_orders,
    (SELECT MAX(apply_date) FROM apply_orders) AS latest_apply_date;
