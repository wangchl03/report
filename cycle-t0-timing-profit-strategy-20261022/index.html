召回策略：从单一D0提单率转向新增利润

保留当天高意愿、高预期利润用户的转化，分阶段经营尚未提单用户。不要为了提高当天指标广泛加补贴，也不要因为晚提单组历史盈利率较高就主动压后全部用户。

阶段循环贷结清续贷T0共同考核
D0确认仍有在途、当前无逾期且获额有效。区分还款带来的进页与主动提单意愿。确认干净结清后的最新获额仍通过，优先承接主动选择金额、查看计划等明确意愿。新增有效提单及放款。同步看金额、预测利润、补贴成本。
D1—D3对仍具循环贷资格且未提单者分层召回，避免已结清后继续套用循环贷标签。对获额仍通过的未提单用户分层触达，核对额度、日息和页面转化问题。分别统计累计提单和新增利润，检查是否仅将D4—D15需求提前。
D4—D7先复核在途与逾期资格，再考虑触达，不以历史事件标签代替实时资格。区分被拒、可提单但未活跃、有互动未提交三类状态。以用户为单位去重触达，跨循环贷和T0合并管理。
D8—D15只在资格有效及预期利润为正的人群测试较低频触达。按历史价值、产品条件与需求分层，不把阶段性未提单当作永久流失。使用完整到期结果复核收益，避免9月晚提单样本的到期选择偏差。

下一步验证方式

按用户随机分配“现有策略”“加强D0触达”“D0加D1—D7分阶段触达”三组，跨产品保持同一分组。主指标采用15日累计新增放款及扣除触达、优惠成本后的新增利润，D0提单率作为过程指标；在相同到期成熟度下复核风险和盈利。

本次为历史描述性比较，不包含新增召回成本、实验对照或可识别的增量效果，不能给出可信的最优补贴金额与确定收益提升。

指标口径与可比性核对

事件范围：2026年1月1日至9月30日获额通过事件，按获额通过日期分月。America/Belize自然日。

T0事件：recycle_type=3、loan_type_code=2且获额通过。同用户在该获额当日、获额之前曾干净结清，结清后当时已放款未结清订单数为0。不是只结清任意一单。

循环贷事件：recycle_type=2、loan_type_code=2且获额通过。获额时有在途，后续首次提单时仍有在途。获额至首次提单前出现分期逾期，或在途全部结束，记未有效提单。

去重与归因：两类各自先按同一订单最新获额，再按同用户相邻间隔≤20秒链式归批，取最新获额，同秒取最大订单号。提单可为其他订单。同秒多笔提单取最小订单号。

展开完整指标定义

观察差异：T0沿用既有下一次T0获额截断，保证首次提单归属唯一。循环贷每次获额独立观察。下表给出T0同样独立观察的对照。

提单率：该阶段首次有效提单获额事件数÷本类入样获额事件数。分子不要求最终放款或到期。同一事件最多归入一个阶段，用户可贡献多次事件。

盈利率：首次提单已放款且到期的订单，(SUM(repaid_amt)−SUM(remit_amt))÷SUM(remit_amt)。只用该次首次提单，不跳过失败提单改取后续放款。回款不限制日期。

已到期：is_remit=1、remit_amt>0、is_due=1、有效due_date且due_date严格早于业务统计日。当前状态8订单仍保留。未扣资金、获客与运营成本。

汇总与重复：月度和阶段内订单去重；合计跨月重新去重；D1—D15及D0—D15合并时再次订单去重。各阶段金额不能直接加总，盈利率不是各月或各阶段百分比的算术平均。

数据时点：两类金额来自同一只读可重复读快照，北京时间2026-10-22 11:19:36。业务统计日2026-10-21。循环贷历史资格复用2026-10-19已审计标签，T0历史资格本次读取；未宣称两类历史标签在同一时点重建。

完整性：所有D0—D15提单观察窗口均已成熟，不把未成熟观察记为未提单。订单到期成熟是另一概念，9月部分订单仍未到期。

WITH
/* 一、统一日期、秒数和观察时点。无穷大只用于尚未整笔结清的区间右端。 */
params AS (
 SELECT DATE '2026-01-01' AS start_date, DATE '2026-10-01' AS end_date_exclusive,
  0::int AS shard_id,4::int AS shard_count,
  CURRENT_TIMESTAMP AT TIME ZONE 'America/Belize' AS asof_local,
  EXTRACT(EPOCH FROM TIMESTAMPTZ '2026-01-01 00:00:00-06:00')::double precision AS start_epoch,
  EXTRACT(EPOCH FROM TIMESTAMPTZ '2026-10-01 00:00:00-06:00')::double precision AS end_epoch,
  EXTRACT(EPOCH FROM CURRENT_TIMESTAMP)::double precision AS asof_epoch,
  EXTRACT(EPOCH FROM (CURRENT_DATE::timestamp AT TIME ZONE 'America/Belize'))::double precision AS complete_before_epoch,
  9000000000000000000::double precision AS open_end_epoch
),
/* 二、通过的循环贷获额；同用户同订单保留统计期内最新通过时间。
   vir_date筛选沿用原提取脚本，仅作分区裁剪，最终范围由vir_unix决定。
   EXISTS防止类型表关联放大，不与结清续贷流失用户表关联。 */
raw_offer AS (
    SELECT
        v.user_id::bigint AS user_id,
        v.serial_id::bigint AS serial_id,
        MAX(v.vir_unix)::double precision AS offer_epoch
    FROM wangchuanliang.order_vir_f_copy v
    CROSS JOIN params p
    WHERE v.is_pass1=1 AND v.loan_type_code=2 AND MOD(v.user_id,p.shard_count)=p.shard_id
      AND v.user_id IS NOT NULL AND v.serial_id IS NOT NULL
      AND v.vir_unix>=p.start_epoch-86400 AND v.vir_unix<p.end_epoch+86400
      AND v.vir_date>=DATE '2025-12-30' AND v.vir_date<DATE '2026-10-03'
      AND EXISTS (
          SELECT 1 FROM wangchuanliang.side_recycle_type_copy r
          WHERE r.serial_id=v.serial_id AND r.recycle_type=2
      )
    GROUP BY v.user_id,v.serial_id
),
/* 三、20秒链式归批。必须先LAG再累加，不能使用FLOOR(时间/20)。 */
offer_lag AS (
    SELECT g.*,
           LAG(offer_epoch) OVER (
               PARTITION BY user_id ORDER BY offer_epoch,serial_id
           ) AS previous_epoch
    FROM raw_offer g
),
offer_batch AS (
    SELECT g.*,
           SUM(CASE WHEN previous_epoch IS NULL OR offer_epoch-previous_epoch>20
                    THEN 1 ELSE 0 END) OVER (
               PARTITION BY user_id ORDER BY offer_epoch,serial_id
               ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
           ) AS batch_id
    FROM offer_lag g
),
offer_rank AS (
    SELECT g.*,
           ROW_NUMBER() OVER (
               PARTITION BY user_id,batch_id ORDER BY offer_epoch DESC,serial_id DESC
           ) AS batch_rn,
           COUNT(*) OVER (PARTITION BY user_id,batch_id) AS batch_record_count,
           MIN(offer_epoch) OVER (PARTITION BY user_id,batch_id) AS batch_first_epoch,
           MAX(offer_epoch) OVER (PARTITION BY user_id,batch_id) AS batch_last_epoch
    FROM offer_batch g
),
offer_dated AS (
    SELECT g.*,
           (TO_TIMESTAMP(offer_epoch) AT TIME ZONE 'America/Belize')::date AS offer_date,
           (TO_TIMESTAMP(batch_first_epoch) AT TIME ZONE 'America/Belize')::date AS batch_first_date,
           (TO_TIMESTAMP(batch_last_epoch) AT TIME ZONE 'America/Belize')::date AS batch_last_date
    FROM offer_rank g CROSS JOIN params p
    WHERE g.batch_rn=1 AND g.offer_epoch>=p.start_epoch AND g.offer_epoch<p.end_epoch
),
/* 仅上述范围原始获额用户的历史订单参与；保留未20秒去重范围用于前后对账。 */
candidate_users AS (SELECT DISTINCT user_id FROM raw_offer),
/* 四、提单/放款/结清原始时间。有效timestamp优先，提单/放款才允许unix回退。
   与原提取一致：这层从2026年起提单记录及年初仍可能在途订单取数。
   观察期末是原取数时点，不是10月10日，否则D7结果会被截断。 */
loan_source AS (
    SELECT o.user_id::bigint AS user_id,o.serial_id::bigint AS serial_id,
           CASE WHEN o.apply_time>=TIMESTAMP '2000-01-01'
                THEN EXTRACT(EPOCH FROM o.apply_time AT TIME ZONE 'America/Belize')::bigint
                WHEN o.apply_unix>0 THEN o.apply_unix::bigint END AS app_epoch,
           CASE WHEN o.remit_time>=TIMESTAMP '2000-01-01'
                THEN EXTRACT(EPOCH FROM o.remit_time AT TIME ZONE 'America/Belize')::bigint
                WHEN o.remit_unix>0 THEN o.remit_unix::bigint END AS fund_epoch,
           CASE WHEN o.repaid_time>=TIMESTAMP '2000-01-01'

    FROM wangchuanliang.order_loan_f_v2_copy o
    JOIN candidate_users u ON u.user_id=o.user_id
    CROSS JOIN params p
    WHERE (o.apply_time>=p.start_date::timestamp AND o.apply_time<=p.asof_local)
       OR (o.is_remit=1 AND (
              o.repaid_time>=p.start_date::timestamp
              OR o.repaid_time<TIMESTAMP '2000-01-01' OR o.repaid_time IS NULL
          ))

loan_distinct AS (SELECT DISTINCT * FROM loan_source),
loan_conflict_users AS (
    SELECT user_id FROM loan_distinct
    GROUP BY user_id,serial_id HAVING COUNT(*)>1

loan_quality AS (
    SELECT l.*,
           CASE WHEN is_remit=1 AND (
               fund_epoch IS NULL
               OR ((COALESCE(is_repaid,0)=1 OR COALESCE(loan_status_code,0)=7)
                   AND settle_epoch IS NULL)
               OR (settle_epoch IS NOT NULL AND settle_epoch<fund_epoch)
           ) THEN 1 ELSE 0 END AS bad_lifecycle
    FROM loan_distinct l
),
/* 当前状态7仅用于发现“标记结清却无结清时间”的异常，不用于套用历史状态。 */
loan_bad_users AS (SELECT DISTINCT user_id FROM loan_quality WHERE bad_lifecycle=1),
funded AS (
    SELECT l.user_id,l.serial_id,l.fund_epoch::double precision AS fund_epoch,
           COALESCE(l.settle_epoch::double precision,p.open_end_epoch) AS end_epoch
    FROM loan_quality l CROSS JOIN params p
    WHERE l.is_remit=1 AND l.bad_lifecycle=0 AND l.fund_epoch<=p.asof_epoch
      AND (l.settle_epoch IS NULL OR l.settle_epoch>p.start_epoch)

/* 五、分期逾期：包括已还分期，绝不能额外加is_repaid_period=0。 */
period_source AS (
    SELECT q.user_id::bigint AS user_id,q.serial_id::bigint AS serial_id,
           COUNT(*) AS rows_n,COUNT(DISTINCT q.current_term) AS terms_n,
           MIN(CASE WHEN q.overdue_days_period>0 THEN q.due_date_period::date END) AS first_positive_due,
           SUM(CASE WHEN q.overdue_days_period>0 AND (
               q.due_date_period IS NULL OR q.due_date_period<DATE '2000-01-01'
           ) THEN 1 ELSE 0 END) AS bad_positive_due,
           SUM(CASE WHEN q.overdue_days_period IS NULL THEN 1 ELSE 0 END) AS null_overdue,
           SUM(CASE WHEN q.current_term IS NULL THEN 1 ELSE 0 END) AS null_terms
    FROM wangchuanliang.repayment_plan_v2_copy q
    JOIN candidate_users u ON u.user_id=q.user_id
    CROSS JOIN params p
    WHERE q.is_remit=1 AND (
        q.repaid_time>=p.start_date::timestamp
        OR q.repaid_time<TIMESTAMP '2000-01-01' OR q.repaid_time IS NULL
    )
    GROUP BY q.user_id,q.serial_id
),
funded_period AS (
    SELECT f.*,q.serial_id AS period_serial_id,q.rows_n,q.terms_n,
           q.bad_positive_due,q.null_overdue,q.null_terms,q.first_positive_due,
           CASE WHEN q.first_positive_due IS NOT NULL THEN
               EXTRACT(EPOCH FROM ((q.first_positive_due+1)::timestamp
                         AT TIME ZONE 'America/Belize'))::double precision
           END AS overdue_start_epoch
    FROM funded f LEFT JOIN period_source q
      ON q.user_id=f.user_id AND q.serial_id=f.serial_id
),
period_bad_users AS (
    SELECT DISTINCT user_id FROM funded_period
    WHERE period_serial_id IS NULL OR bad_positive_due>0 OR null_overdue>0 OR null_terms>0
       OR (overdue_start_epoch IS NOT NULL AND (
              overdue_start_epoch<fund_epoch OR overdue_start_epoch>=end_epoch
          ))
),
invalid_users AS (
    SELECT user_id FROM loan_conflict_users
    UNION SELECT user_id FROM loan_bad_users
    UNION SELECT user_id FROM period_bad_users
),
usable_funded AS (
    SELECT f.* FROM funded_period f
    WHERE NOT EXISTS (SELECT 1 FROM invalid_users x WHERE x.user_id=f.user_id)
),
/* 六、把多笔在途区间合并成连续在途段。
   必须与“此前所有区间最大结束时间”比较，不能只LAG上一行结束时间，

   但首次提单的既有在途条件另用fund_epoch<app_epoch严格检查。 */
funded_running AS (
