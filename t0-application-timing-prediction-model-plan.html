T0 APPLICATION TIMING MODEL · DEVELOPMENT BLUEPRINT

T0用户 D0 / D3 / D7 / D15
提单概率预测模型构建方案

在用户完成结清、0在贷并重新获额通过的时点，预测其当天、3日内、7日内和15日内首次提单概率，为触达时机、息费让利和产品推荐提供统一排序依据。

方案版本：V1.0　｜　生成日期：2026年10月7日　｜　主口径：口径1｜用户后续提单率

结论目标与边界样本与标签模型架构特征体系训练验证评分输出自动迭代实施计划附录

首版推荐

采用离散时间生存模型：将每个T0事件展开为四个观察区间，在用户尚未提单的前提下，依次估计D0、D1—D3、D4—D7、D8—D15发生首次提单的条件概率，再转换为四个累计概率。

业务结果：不仅知道“会不会提单”，还知道“更可能在哪个时间段提单”，从而区分立即触达、等待自然转化、延迟触达和重点让利客群。

二、模型目标与使用边界

核心问题

用户多久会首次提单？

  • 在T0获额通过时点输出四个累计概率。
  • 主目标使用口径1｜用户后续提单率。
  • 不要求后续提单与本次获额订单具有相同serial_id。
  • 同一用户后续首次提单只归属于提单前最近一次T0事件。
不回答的问题

模型不是因果结论

  • 低提单概率不等于“给券一定有效”。
  • 风控分用于描述与排序，不证明风险导致不提单。
  • 让利效果必须通过随机对照实验或uplift模型验证。
  • 口径2的原获额订单使用率可作为旁路监控，不与主标签混用。

评分时点

as_of_time = 20秒批次去重后保留的T0获额通过时间 vir_time。所有模型特征必须在该时点已经发生并可被业务系统取得。

重复事件与右删失

如果用户在首次提单前又产生新的T0事件，后续提单归给最近一次事件；上一事件在新事件发生时停止观察。停止后的区间按右删失处理，不能错误标记为“未提单负样本”。

四、模型架构：统一离散时间生存模型

训练数据形态

事件展开为“事件 × 区间”

每个T0事件最多展开四行。只有在前一区间尚未提单且仍在观察中的事件，才进入下一区间。

  • interval_id=0：预测D0发生提单。
  • interval_id=1：条件于D0未提单，预测D1—D3。
  • interval_id=2：条件于D3未提单，预测D4—D7。
  • interval_id=3：条件于D7未提单，预测D8—D15。
推荐算法

逻辑回归基线 + LightGBM主模型

在同一张长表上训练条件风险概率。逻辑回归用于验证方向与可解释性，LightGBM用于学习额度变化、借款次数、风控分和近期行为之间的非线性交互。

  • 类别特征采用稳定编码，避免全历史目标编码泄漏。
  • 样本权重可纠正不同区间和月份的分布差异。
  • 最终累计概率必须进行时间外校准。
条件概率
h0=P(D0提单)；h1=P(D1—D3提单 | D0未提)；依此类推。
P(D0)
p_d0 = h0
P(D3)
p_d3 = 1 − (1−h0)(1−h1)
P(D7)
p_d7 = 1 − (1−h0)(1−h1)(1−h2)
P(D15)
p_d15 = 1 − (1−h0)(1−h1)(1−h2)(1−h3)

结构优势

由同一组条件概率推导累计概率，可保证每个用户都满足p_d0 ≤ p_d3 ≤ p_d7 ≤ p_d15，避免四套独立二分类模型出现“3日概率高于7日概率”的业务冲突。

5.1 两个风控模型分的固定处理规则

405模型分

KabyBXgboost405Apd7CreCyc

  • 以当前T0保留订单serial_id关联。
  • 原始分数单独入模。
  • 缺失或无效值-9999999转为空值并增加缺失标记。

363模型分

KabyBXGBoost363Dpd7Cre

  • 以当前T0保留订单serial_id关联。
  • 原始分数单独入模。
  • 缺失或无效值-9999999转为空值并增加缺失标记。

不合并两个分数

不取平均、不择一替代。可在验证尺度一致后增加分位数差、共同缺失标记和交互项，但两个原始模型分必须保留，以便模型分别学习其增量信息。

5.2 额度使用率

历史订单使用率
上一笔/历史提单金额 ÷ 对应获额额度。分子不是放款金额。
0%处理
使用率为0不视为正常订单，设为缺失，并增加utilization_missing_flag=1。
超过100%
属于可能使用提额红包的有效业务现象，保留原值，并增加utilization_over_100_flag=1。
当前T0订单
用户尚未提单，当前订单使用率未知，不能用0填充，也不能进入T0时点评分。

明确禁止的泄漏字段

当前T0事件获额后的页面行为、下一笔提单金额、下一笔额度使用率、下一笔放款状态、未来还款/逾期/盈利，以及获额后更新的风控结果，均不能进入首版T0时点模型。

六、训练、验证与概率校准

训练集

较早月份

使用已完整走完D15窗口的历史事件训练；按时间顺序构造，不随机打乱未来月份。

验证集

后续月份

选择模型、特征和参数；验证完成后冻结方案，避免反复查看测试集调参。

测试集

最新成熟月份

仅用于最终时间外评估，模拟模型上线后面对新月份的真实表现。

评估维度指标验收重点
排序能力AUC、PR-AUC、KS、Top 10%/20% Lift、Top-K提单覆盖率每个累计窗口分别评估，不能只看总AUC
概率准确度Log Loss、Brier Score、校准曲线、ECE预测70%的客群，实际提单率应接近70%

客群公平性按借款次数、额度变化、风险档、平台、产品分层重点识别局部失效和样本不足

概率校准

在时间外验证集上比较Isotonic与Platt校准，按D0、D3、D7、D15累计概率分别检查校准度。校准器只能用验证期拟合，不能读取测试期结果。

八、自动训练与特征迭代机制

固定数据与评估协议

冻结T0母表、标签窗口、成熟度、训练/验证/测试月份和核心指标。任何模型版本都必须在同一时间外测试集比较。

建立特征注册表

每个特征记录业务含义、来源表、SQL、窗口、空值规则、上线可用性和版本；自动阻止使用as_of_time之后的数据。

候选特征分组实验

按“基础画像→两项风控分→最近1/2/3次获额→最近1/2/3次提单→历史行为→还款价值”逐组增加，记录每组对时间外Lift与校准的边际提升。

Champion–Challenger

当前线上模型为Champion，新模型为Challenger。只有在排序、校准、稳定性和核心客群表现均通过阈值后才替换，不能因为单次AUC更高自动上线。

周期重训与漂移触发

按月重训；若风控策略、产品息费或获额规则改变，提前触发重训。自动生成特征缺失、PSI、校准和分层Lift报告。

自动化边界

可以自动生成特征、训练、调参和评估，但不能不断使用同一测试集反复优化。测试集一旦用于模型选择，就失去独立性；需要滚动到新的成熟月份重新做时间外验证。

标签生成伪代码
for each strict_t0_event e:
    start = e.vir_time
    stop  = min(e.next_t0_time, data_cutoff_ts, e.vir_date + 16 days)

    applications = same_user_applications where apply_time >= start and apply_time < stop
    first_apply  = earliest(applications)

    if first_apply is null:
        outcome_bucket = "NO_APPLY_BY_D15"  # 仅在D15窗口成熟时作为完整负样本
    else if first_apply < e.vir_date + 1 day:
        outcome_bucket = "D0"
    else if first_apply < e.vir_date + 4 days:
        outcome_bucket = "D1_D3"
    else if first_apply < e.vir_date + 8 days:
        outcome_bucket = "D4_D7"
    else:
        outcome_bucket = "D8_D15"

    # 若next_t0_time提前终止且尚未提单，后续区间为右删失，不标记为负样本
长表展开伪代码
intervals = [D0, D1_D3, D4_D7, D8_D15]

for each event e:
    for interval in intervals:
        if e is still under observation at interval start:
            emit row(
                event_id       = e.event_id,
                interval_id    = interval,
                event_flag     = 1 if first_apply falls in interval else 0,
                exposure_days  = interval length,

评分概率转换伪代码
h0, h1, h2, h3 = model.predict_hazard(features, interval_id=[0,1,2,3])

p_d0  = h0
p_d3  = 1 - (1-h0)*(1-h1)
p_d7  = 1 - (1-h0)*(1-h1)*(1-h2)
p_d15 = 1 - (1-h0)*(1-h1)*(1-h2)*(1-h3)

p_d1_3  = p_d3  - p_d0
p_d4_7  = p_d7  - p_d3
p_d8_15 = p_d15 - p_d7
p_no_apply_d15 = 1 - p_d15
上线前强制校验
  • 母表只包含is_pass1=1、recycle_type=3的结清续贷事件。
  • 20秒链式去重顺序固定，批内保留最晚获额、同时间最大订单号。
  • 同一提单只归属最近一次T0事件。
  • D0、D3、D7、D15分别使用对应成熟样本。
  • 两项风控分均保留原始值和独立缺失标记。
  • 使用率0记为缺失，超过100%保留并标记。
  • 生产概率单调违规率为0，模型版本与特征版本完整回写。
