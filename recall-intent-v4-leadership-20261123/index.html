REPORT

管理层摘要

范围：原V4（2026年10月22日冻结），不含V4Pro及T0模型。近两个月按2026年10—11月界定；已核验应用留档覆盖10月23日至11月16日五批。

管理层先看这四点

  • 建立目的：在满足召回与风险准入条件的用户中，识别未来96小时更可能提单的用户，为触达顺序、资源分配和策略分层提供依据。
  • 历史效果：10月16日历史留出样本31,499人中，V4的AUC为0.8857，优于同样本V2的0.8710；前20%高分用户覆盖80.59%的提单用户。该验证在10月22日冻结模型后执行。
  • 近期表现：本次用五批留存原始分数核对实际订单，AUC为0.8801—0.8834，前20%覆盖79.23%—81.18%。覆盖50,956名不同用户、175,837个批次人次，近期排序能力保持稳定。
  • 应用边界：已证明可以批量重建特征、评分并输出名单；尚未取得完整的生产发分、策略触达与成本收益闭环证据。当前结果支持“识别提单倾向”，尚不能量化模型带来的增量利润。

本次建议领导决策

继续将原V4作为召回排序工具受控使用，保留既有风险准入与策略规则；优先建设每天可复用的特征快照、评分留档及结果监测。随后开展预先锁定口径的随机AB测试，验证模型指导的策略是否增加净收益。

特征压缩作为下一阶段研究：1,090个输入中654个在当前模型中分裂增益为0，有明显降本空间。压缩模型必须重新验证后再决定替换，不能凭重要性排序直接删列上线。

REPORT

业务目的与模型迭代

业务问题与预期价值

同一批流失用户的近期需求差异很大。仅按流失天数、历史借款次数或单一活跃规则分层，难以把有限触达资源集中到更可能提单的用户。V4综合行为变化和借还款生命周期，输出可排序的提单概率。

业务上应分别评价三件事：识别能力是否提高、资源分配是否更有效、最终净收益是否增加。前两者需要评分与执行记录，最后一项还需要对照实验、券成本和成熟贷后结果。高分用户可能自然就会提单，因此高分不直接等于应发更大红包。

迭代过程中的取舍

未证明收益的V3没有自动替换基线；V4也保留原V2文件与默认配置。对领导应强调：每次升级以时间验证和可追溯证据为依据，研究候选、批量评分能力、正式生产部署是不同里程碑。

依据：[S1][S7]。V1为历史报告记载，未在本次重新训练复现；V4Pro是另外的研究分支，不并入本报告成绩。

模型定义、数据与适用范围

项目原V4定义
预测对象能确定最近一次全部结清时点、当前成功放款在贷数为0，且结清后达到至少7个业务自然日的适用用户。名单风险过滤另行执行。
预测目标特征截止T，按冻结协议指定的目标起点S观察[ S, S+96小时 )内是否任意实际提单，S不早于T；不要求审批通过或成功放款。本次五批S=T。
分数含义模型经Platt校准后的概率p；业务展示可用100×p。分数越高，预测提单倾向越高。
时间要求特征只使用T之前可见事件；数据库业务时区America/Belize，与北京时间相差14小时。
不适用处理结清不足7天、有在贷或无法可靠重建必要范围的用户，保留不适用原因，不把缺少分数解释成低意愿。

数据来源与质量处理

金融数据来自order_loan_f_v2_copy、order_vir_f_copy、side_recycle_type_copy、repayment_record_copy及repayment_plan_v2_copy；行为数据来自旧SDK的event_track_record。原V4未采用user_behavior_track_record、user_behavior_track，这两张新SDK表属于后续研究方向。

明确区分“观察到没有事件”和“来源缺失或历史覆盖不足”：后者保留缺失值。字段转为数值，非有限值转缺失，再按模型规定顺序输入。原V4不对全部特征统一填0，也不把后续行为回填到过去。

依据：[S2][S7]。券相关输入主要是页面行为；实际输入不含显式息费定价字段。确认按钮点击不能替代订单表的实际提单。

特征如何筛选，哪些特征最有用

筛选过程为：1,929个完整候选 → 1,283个紧凑候选 → 用训练数据剔除常量和缺失率达到99.5%的字段 → 最终1,090个输入。候选定义、过滤、正则和模型选择结合使用，并非先看最终测试成绩再逐个挑字段。

关键计算口径

  • 行为窗口包括逐日d1—d7、近3/7/30天、第8—15天、第16—30天；同时保留全行为及剔除实际还款自然日的nonpay支线。
  • 额度使用率按同一订单提单金额除以匹配获额金额，形成末笔、近3笔均值、历史均值/中位数等摘要。本报告沿用冻结V4定义，未套用后来新增的归一规则。
  • 提单间隔等特征仅在两端事件均已发生于T之前时计算；未回访用户不能用未来第一次回访补齐历史间隔。

算法与控制复杂度

最终选用LightGBM并做Platt概率校准。关键配置包括31个叶节点、最大深度7、叶节点最小样本100、学习率0.03、L1=0.2、L2=10及列采样。滚动验证采用60轮早停，按折内最佳轮数中位数确定最终81棵树。

选型以开发样本的PR-AP为主要优选指标，并设置相对V2的AUC、前20%捕获率门槛，再参考头部覆盖与概率损失。原始V2作为固定基线保留；1009的选型用户与校准用户互斥。

可以保证到什么程度

已有18项合成时间边界检查及金融特征未来裁剪检查支持代码按T截断事件；但历史源表是当前副本，首次入库时点、回补和计划版本变化未完全还原。因此1016应称“冻结后历史留出验证”，不能声称在10月16日当天已经完成了严格实时预测。

历史1016批次的T为10月16日01:37:20，目标起点S为02:11:02（均业务时间）；其0.8857对应S起96小时。1009的T为10月9日23:49:06，S为10月10日00:07:31。本次新增五批则以各自留存T起96小时核验。

依据：[S1][S3][S7]。训练标签最晚结束于10月4日；1009之后的开发标签用于选型/校准，其作用须与排序拟合分开说明。

如何翻译成业务语言

如果按V4分数只观察最高的20%用户，可以覆盖约80.59%的实际提单用户；这一组的提单率为8.30%，约为全样本的4.03倍。这说明模型能集中识别提单倾向较高的用户，可用于安排触达优先级。它不表示给这组发券能把提单率提高4倍。

提升的可靠性与保留意见

配对用户重采样得到：AUC差值95%区间为+0.0083至+0.0211，PR-AP差值为+0.0366至+0.0793；两者支持V4优于V2。前20%捕获率差值区间为−0.48至+4.30个百分点，跨过0，因此“前20%覆盖一定提高”证据尚不充分。

升级收益主要体现在整体排序、稀少正例的识别和概率质量。因提单是低基率事件，不使用“准确率很高”作为主结论：全部预测不提单也可能获得很高准确率，却没有业务价值。

依据：[S1][S3]。区间来自既有300次配对用户重采样；用于量化当前样本的不确定性，不能保证未来批次始终同幅提升。

对特征数量的真实判断

只有436个字段在当前模型中有正分裂增益，前30项贡献约68.97%。同时，同算法重建16字段对照的1016 AUC为0.8855，接近V4；其PR-AP为0.1603，低于V4的0.2006。复杂特征在部分指标上有价值，但不代表1,090个字段都必须长期保留。

建议的压缩验证路径

  • 先按业务语义合并重复窗口，识别高相关字段、来源脆弱字段、缺失严重字段；保留缺失与无事件的区别。
  • 仅在训练/开发范围内，通过时间滚动、分组置换及特征组消融筛选候选；同时观察AUC、PR-AP、头部捕获、概率误差与取数耗时。
  • 冻结候选后，用新的、标签已成熟且未参与选型的时间批次一次性比较，并补充严格用户隔离验证。原1016及本次五批既已看过，不再作为未触碰的最终测试。
  • 满足业务预先设定的非劣效与成本要求后，再并行试运行及切换版本。原V4字段接口保持冻结，压缩模型另行命名和留档。

依据：[S3][S8]。尚未在本次训练任何压缩模型；以上为下一阶段建议，不是已实现提升。

生产应用与增量收益验证方案

建议的日常生产流程

每天固定截点生成可追溯特征快照 → 检查召回/风险准入及模型适用性 → 使用冻结版本评分 → 依规则分配触达与券策略 → 保存执行结果 → 标签成熟后回填提单/放款/贷后结果。以下为建议目标流程，部分能力已有本地实现，自动化闭环尚待验收。

层次建议保留的数据与控制
特征层user_id、feature_asof、数据覆盖截止、来源版本、缺失原因；金融与行为特征分层，按用户和快照日期唯一。
评分层模型版本/hash、字段版本、原始概率、展示分、适用标记、生成/发布时间、数据校验结果。分数不因当批最高值变化而重新缩放。
策略层名单来源、策略版本、实验分组、随机化时间、券金额/幅度/有效期、计划与实际触达时间、发放结果。
监控层用户覆盖与不适用率、特征缺失/分布漂移、跑数耗时；成熟96小时AUC/AP、头部捕获、分层实际率与校准。
贷后与收益层成熟到期订单量、本金、repaid_amt、逾期和券/触达成本；统计截止、成熟期限与重叠用户归属须固定。

用随机AB回答“是否值得发券、怎样用模型”

  • 在同一合格召回池中，按批次和关键风险/意愿分层随机分组：对照执行原策略，实验执行模型指导的新策略；按用户固定分组，避免跨批重复曝光污染。
  • 预先锁定一个主要目标、最小有意义提升、样本量和停止规则。建议以每名分配用户的增量净收益为长期主目标，96小时提单率作为早期指标，逾期与投诉等作为约束。
  • 按分配分组统计全部用户（ITT），不用“实际领取券/已提单用户”替代随机分母；分别报告执行合规率、风险、成本及不确定性。

盈利统计延续已确认口径：在同一到期订单集合内，到期回收盈利金额=Σrepaid_amt−Σ到期放款本金；盈利率用合计金额相除。该指标须与扣除券、触达及其他成本后的净收益区分；也不能把96小时提单率直接折算为利润。

建议交付顺序

第一阶段补齐快照与发布日志并建立周监控；第二阶段冻结压缩候选及新验证集；第三阶段做等口径AB并等待贷后成熟。每一步均以数据质量、时间可用性和业务验收结果决定是否推进。

以上为实施建议，未给出未经核验的上线日期、收益金额或承诺提升。

领导可能追问

1. 分数80是不是80%的用户会提单？

只有score=100×原始校准概率时，80才表示模型预测概率80%；部分历史导出使用0—1分数，另有最高分缩放文件。正式使用必须核验单位，当前五批原始预测均值约1.7%—2.0%。

2. 为什么有1,090个特征，不是越少越好吗？

多窗口有助于刻画变化，但当前60%的输入零增益，存在明显冗余。应把效果、取数成本、稳定性一起优化；削减后须重新训练并在新留出验证。

3. AUC 0.88意味着88%的用户会提单吗？

不是。它评价模型把真实提单用户排在未提单用户前面的能力。实际提单率和头部提单率应单独看。

4. 高分用户是否应该发更多优惠？

需要实验。高分用户也可能自然提单，最值得优惠的人应由策略增量收益决定；意愿分提供分层，不独自决定优惠额度。

5. 能否说已经没有过拟合、生产稳定两个月？

不能这样表述。近期五批排序稳定是积极证据；用户重合、历史回补、较早滚动波动仍存在。原V4在10月22日冻结，尚不足两整月，自动生产执行链路也未完全核验。
