01

统计对象与统一范围

统计粒度为统一截止时点A下，每位用户一行。以全生命周期循环贷成功放款恰好4笔的用户为对象，以下四项准入条件须在同一快照同时满足。

准入条件统一业务口径
循环贷成功放款恰好4笔截至A，recycle_type=2的成功放款订单数恰好为4。成功放款要求is_remit=1、remit_amt>0，放款时间有效且apply_time ≤ remit_time < A。实际循环贷提单次数可以大于4。
最新获额为循环贷且通过先剔除无效获额recycle_type=1，在类型2、3的全部原始获额中，按credit_time, serial_id倒序定位最新一笔，再要求该笔同时满足recycle_type=2 AND is_pass1=1。不能先筛循环贷或通过记录再选最新；最新有效记录为类型3或未通过时不入选，不回退更早记录。
当前不存在状态8订单用户全部产品当前loan_status_code=8的订单数为0。
当前至少1笔状态5在途订单用户全部产品当前loan_status_code=5的订单数至少为1；不限循环贷，可以有多笔。

状态5在途条件与最新有效原始获额条件，按同一用户、同一截止时点同时判断；不额外要求在途订单与最新获额的serial_id相同。

业务时区统一为America/Belize；事件发生时间早于A，覆盖源数据可用的完整生命周期。永久排除用户5101518。实际订单按user_id + serial_id去重，包含失败、取消及未成功放款的实际提单。

本说明共84项业务特征：常规4项，第1、2、3笔各19项，第4笔23项。数据库另有29项用户、时间、订单及准入辅助列，不计入84项业务特征。每项均可按F编号与英文字段名定位。

02

时间锚点与统计窗口

先从用户成功放款的循环贷订单中，按apply_time, serial_id升序编号，依次定位O1、O2、O3、O4。T1—T4取各订单的提单时间，R1—R4取其实际放款时间；不按实际放款时间重排四个锚点。

符号含义
A / D本次统一截止时点A，以及对应的Belize业务日期D。
Oi / Ti第i笔成功放款循环贷订单，以及该订单的提单时间，i为1、2、3或4。未成功放款的循环贷提单不占Oi序号。
RiOi的实际放款时间，即Oi.remit_time。其中R4=O4.remit_time为F81、F82放款后获额窗口的起点。
PiTi之前已经成功放款的全产品最后一笔订单，按remit_time, apply_time, serial_id倒序定位；不存在则为NULL，不强制为上一笔循环贷。
C(Oi) / C(Pi)Oi、Pi按各自原始通过获额及获额日规则选出的额度。
U(Oi) / U(Pi)对应订单各自的apply_amt / 选定额度。

六个独立统计窗口

窗口获额时间范围使用字段
第一阶段credit_time ≤ T1第1笔的获额次数、单/双产品次数及阶段提单率，次数记N1。
第二阶段T1 < credit_time ≤ T2第2笔的阶段获额特征，次数记N2。
第三阶段T2 < credit_time ≤ T3第3笔的阶段获额特征，次数记N3。
第四阶段T3 < credit_time ≤ T4第4笔的阶段获额特征，次数记N4。
截至第四笔的累计credit_time ≤ T4F83累计获额次数、F84累计提单率，次数记N累计。
第四笔实际放款之后R4 < credit_time < AF81首次、F82最近一次通过循环贷获额距截止日的自然日天数。

各阶段边界使用提单时间Ti。恰好等于T1的获额归第一阶段；恰好等于T2、T3、T4的获额归各自阶段。阶段起点不改为上一笔实际放款时间。累计窗口独立去重，不能将四个阶段次数直接相加。

F81、F82严格从第四笔实际放款R4起算。恰好等于R4或A的获额不进入放款后窗口，不用T4替代R4，也不使用放款前获额补值。

03

通过获额去重与产品识别

获额类型业务含义使用规则
recycle_type=1无效获额不计获额次数，不关联订单获额属性，也不连接20秒链。其实际订单仍保留在全产品订单历史与当前状态检查中。
recycle_type=2循环贷获额六窗获额特征仅使用loan_type_code=2 AND is_pass1=1的通过记录。
recycle_type=3结清续贷获额不混入循环贷阶段或累计获额次数。作为原始订单获额属性来源时，仍要求is_pass1=1。

先筛通过、切窗，再独立20秒相邻链去重

六窗均先保留loan_type_code=2 AND recycle_type=2 AND is_pass1=1，再按各窗时间边界切出记录。同一用户在每个窗口内，按credit_time, serial_id排序，相邻通过获额间隔不超过20秒归为同一链。每链保留时间最晚一笔，同刻保留serial_id最大一笔。

相邻链可以传递连接，例如第0、15、30秒的三条通过获额归为一链。失败、类型1及类型3记录不计数，也不能作为中间记录连接循环贷去重链。阶段、累计与放款后窗口分别去重，不跨窗口连接。

单产品、双产品与订单属性

risk_product按逗号拆分，去首尾空白、空编号及重复编号。不同产品编号恰好1个为单产品，恰好2个为双产品；缺失或3个及以上仍可计入获额总次数，但不强行计入单、双产品次数。

Oi、Pi的额度、单双产品标志、所选产品账期与息费，均按原订单user_id + serial_id关联有效类型2/3且is_pass1=1、credit_time ≤ 对应订单apply_time的原始获额。不能因20秒去重而替换订单编号，不能因属性缺失而改换锚点。

只有匹配到可靠通过获额后，才按原订单product_no读取唯一可靠的产品配置。账期取完整借款期限product.days，须为正整数天；息费取total_fee，须为非负小数费率。未匹配、配置冲突或属性无效时，受影响字段为NULL。

阶段提单率与累计提单率

指标公式分子口径
四个阶段的放款订单提单率1/N1、1/N2、1/N3、1/N4每个阶段固定以对应成功放款订单的1次作为分子；该阶段其他实际提单不增加分子。
F84截至第四笔的累计提单率截至T4实际循环贷提单订单数 / N累计包含未成功放款的实际循环贷提单，按订单去重；分子不固定为4，也不限于匹配获额去重代表订单号。

上述分母为0时均为NULL。累计提单率保存原始小数比例，不封顶；不能用四个阶段提单率的平均值替代。

第四笔放款后的首末获额时间

F81、F82在R4 < credit_time < A内独立去重后，分别取保留代表记录中最早、最近一次获额。最早代表是最早20秒链的最后一笔，不是该链首条原始获额。以截止业务日期D减去代表获额的Belize业务日期，得到自然日天数；不按24小时段计算。

没有合格代表事件时两项均为NULL；只有一个代表事件时两项相等；代表获额发生在截止当天时为0。有值时应满足F81 ≥ F82 ≥ 0。

04

额度选择与小数存储

额度字段切换依据原始关联获额的vir_date，不使用提单日或放款日替代。O1—O4和P1—P4均按各自获额记录独立判断。

获额日期与类型首选字段仅首选为NULL时回退
vir_date ≥ 2025-04-01，全部有效类型max_credit_apply_amtmax_risk_credit_amount
vir_date < 2025-04-01，循环贷类型2max_credit_apply_amtmax_risk_credit_amount
vir_date < 2025-04-01，非循环贷有效类型3max_risk_credit_amountmax_credit_apply_amt

首选额度为0或负数时不回退。选定额度金额保留原始值；额度使用率仅在选定额度大于0时计算。vir_date缺失、额度缺失或非正时，使用率为NULL，不按0%填充，也不参与该指标汇总及有效样本量；超过1的使用率保留原值。

额度使用率 = apply_amt按vir_date选定的额度
额度变化幅度 = C(Oi) − C(Pi)C(Pi)
息费变化幅度 = total_fee(Oi) − total_fee(Pi)total_fee(Pi)

额度使用率变化为U(Oi) − U(Pi)；账期增加天数为本笔完整账期减上笔完整账期；息费增加量为两笔total_fee之差。差值允许为负；计算相对变化幅度时，基准额度或费率须大于0。任一输入缺失时，相关差值或比率为NULL。

统一数值保存

字段类型保存方式
次数整数，真实没有符合条件事件时为0。
金额数值型小数，保留有效精度。
比例与费率小数，例如80%存0.80、负10%存-0.10、60%息费率存0.60；不乘100，不带百分号。
自然日差与账期整数天；平均相邻提单间隔保留小数天。
是否标志1表示是，0表示否，无法判断为NULL。
缺失与精度NULL不按0填充。数值类型不表示统一强制舍入，计算保留有效精度。

用户总提单次数

字段名total_apply_count
