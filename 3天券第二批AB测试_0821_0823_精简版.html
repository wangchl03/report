三、分层召回方案：谁发什么券

先按「第一阶段活跃度」分流，再决定是否补贴。本批数据进一步证明：活跃度是券效果的先决条件。

人群识别信号推荐动作运营逻辑活跃用户结清后4天内有活跃记录（active_days_cnt > 0）30%降息券（聚焦投放）提单率 21.25%、券增量 +2.96pp，是全场唯一有正增量的群体；券价值集中在这一层。沉默用户结清后4天无任何活跃记录默认不发券；先低成本唤醒提单率仅 7.94%，券增量 -0.78pp（发券反而更差）；先唤醒、再观察行为分层。活跃但未进提单页活跃但无提单页浏览/金额切换行为轻提醒 + 小流量验证券需求信号尚弱，避免给本会自然转化的人补贴。活跃且接近决策活跃并进入提单页/切换金额期次30%券 + 到期提醒有明确意愿缺临门一脚，券促成快速决策，前3天集中转化。

附录：完整 PGSQL 代码

以下代码覆盖本报告全部统计。执行前请按实际需要调整统计截止日。

模块一：三批合并 + 前3天提单率（分批次 / 合并，按 ab_group）
-- 数据源：no_apply_0821_0826_30pct / 0822_0827 / 0823_0828
-- 第一阶段 = 结清后到召回前的4天（无提单）；前3天 = 召回日 ~ 召回日+2
WITH t AS (
    SELECT churn_user_id::bigint AS user_id, ab_group,
           DATE '2026-08-26' AS recall_date, '0821_0826' AS batch
    FROM wangchuanliang.no_apply_0821_0826_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, DATE '2026-08-27', '0822_0827'
    FROM wangchuanliang.no_apply_0822_0827_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, DATE '2026-08-28', '0823_0828'
    FROM wangchuanliang.no_apply_0823_0828_30pct
),
apply3 AS (
    SELECT DISTINCT t.user_id, t.batch, t.ab_group
    FROM t
    JOIN wangchuanliang.order_loan_f_v2_copy o
      ON o.user_id = t.user_id
     AND o.apply_date BETWEEN t.recall_date AND t.recall_date + 2
)
-- 分批次
SELECT
    t.batch                                            AS 批次,
    t.ab_group                                          AS 分组,
    COUNT(DISTINCT t.user_id)                           AS 用户数,
    COUNT(DISTINCT a.user_id)                           AS 前3天提单用户,
    ROUND(COUNT(DISTINCT a.user_id) * 100.0
          / NULLIF(COUNT(DISTINCT t.user_id), 0), 2)    AS 前3天提单率
FROM t
LEFT JOIN apply3 a
       ON a.user_id = t.user_id
      AND a.batch = t.batch
      AND a.ab_group = t.ab_group
GROUP BY t.batch, t.ab_group
ORDER BY t.batch, t.ab_group;

-- 三批合并（按 ab_group）
SELECT
    t.ab_group                                          AS 分组,
    COUNT(DISTINCT t.user_id)                           AS 用户数,
    COUNT(DISTINCT a.user_id)                           AS 前3天提单用户,
    ROUND(COUNT(DISTINCT a.user_id) * 100.0
          / NULLIF(COUNT(DISTINCT t.user_id), 0), 2)    AS 前3天提单率
FROM t
LEFT JOIN apply3 a
       ON a.user_id = t.user_id
      AND a.ab_group = t.ab_group
GROUP BY t.ab_group
ORDER BY t.ab_group;
模块二：第一阶段活跃/沉默分层 × ab_group 的前3天提单率
-- 第一阶段活跃 = 宽表 active_days_cnt > 0（结清后4天内有活跃记录）
WITH t AS (
    SELECT churn_user_id::bigint AS user_id, ab_group, active_days_cnt,
           DATE '2026-08-26' AS recall_date
    FROM wangchuanliang.no_apply_0821_0826_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, active_days_cnt, DATE '2026-08-27'
    FROM wangchuanliang.no_apply_0822_0827_30pct
    UNION ALL
    SELECT churn_user_id::bigint, ab_group, active_days_cnt, DATE '2026-08-28'
    FROM wangchuanliang.no_apply_0823_0828_30pct
),
apply3 AS (
    SELECT DISTINCT t.user_id
    FROM t
    JOIN wangchuanliang.order_loan_f_v2_copy o
      ON o.user_id = t.user_id
     AND o.apply_date BETWEEN t.recall_date AND t.recall_date + 2
)
-- 分组 × 活跃
SELECT
    t.ab_group                                          AS 分组,
    CASE WHEN t.active_days_cnt > 0
         THEN '第一阶段活跃' ELSE '第一阶段沉默' END        AS 第一阶段,
    COUNT(DISTINCT t.user_id)                           AS 用户数,
    COUNT(DISTINCT a.user_id)                           AS 前3天提单用户,
    ROUND(COUNT(DISTINCT a.user_id) * 100.0
          / NULLIF(COUNT(DISTINCT t.user_id), 0), 2)    AS 前3天提单率
FROM t
LEFT JOIN apply3 a ON a.user_id = t.user_id
GROUP BY t.ab_group, 2
ORDER BY t.ab_group, 2;

-- 总和（不分 ab_group）
SELECT
    CASE WHEN t.active_days_cnt > 0
         THEN '第一阶段活跃' ELSE '第一阶段沉默' END        AS 第一阶段,
    COUNT(DISTINCT t.user_id)                           AS 用户数,
    COUNT(DISTINCT a.user_id)                           AS 前3天提单用户,
    ROUND(COUNT(DISTINCT a.user_id) * 100.0
          / NULLIF(COUNT(DISTINCT t.user_id), 0), 2)    AS 前3天提单率
FROM t
LEFT JOIN apply3 a ON a.user_id = t.user_id
GROUP BY 1
ORDER BY 1;

数据来源：3天券第二批 30% 降息券 A/B 测试（无券 vs 30%券）。批次：0821_0826、0822_0827、0823_0828（召回日 08-26/27/28）。提单指标为召回后 3 天内首次提单；第一阶段 = 结清后连续 4 天无提单窗口；活跃度用宽表 active_days_cnt 字段（已验证与 event_track 口径一致）。
