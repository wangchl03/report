7 天券的额外 4 天（D4~D7）拉来的是「低质量慢决策用户」。

7 天券与 3 天券前 3 天等价，唯一差异是 D4~D7 仍有效。这 4 天拉来的用户（拖到第 4~7 天才下单的犹豫/被拒用户），盈利率仅 1.75%、逾期率 31.65%——直接拉低了 7 天券的整体盈利质量。

03

「优质用户前置消化」部分成立。

实验组第二周回归用户借款次数 2.41，低于基线 2.67 和对照组 2.79——7 天券第一周提前转化了借款更深的用户，第二周剩余池借款深度下降。

四、核心结论汇总

A

7 天券「量增」：累计提单率 +2.89pp。

实验组 52.71% vs 对照组 49.82%，增量全部来自第一周（+2.87pp，7 天券多覆盖 D4~D7）。

B

7 天券「利减」：盈利率 -20.79pp。

实验组 4.96% vs 对照组 25.75%，逾期率更高（32.52% vs 24.09%）——增量用户的盈利质量显著更差。

C

核心机制：D4~D7 的慢决策用户是「低质量增量」。

7 天券相对 3 天券的唯一差异是 D4~D7 仍有效，而这 4 天拉来的用户盈利率 1.75%、逾期率 31.65%，是盈利恶化的根源。

D

观察期短，结论待复核。

仅 37% 订单到期，样本 206/220 件；且逾期订单暴露更快，早期快照可能高估实验组的逾期率差异。

五、策略建议

A

7 天券不宜盲目扩量，需评估「盈利 vs 提单」的权衡。

7 天券虽提提单 +2.89pp，但盈利率 -20.79pp，增量用户质量差；扩量前应评估让利成本能否被规模效应覆盖。

B

对 D4~D7 才转化的慢决策用户，单独评估其盈利质量。

7 天券的增量集中在 D4~D7 的慢决策用户（盈利率 1.75%、逾期率 31.65%），建议对这些用户加审或压降额度，规避低质量增量。

C

待观察期成熟（≥6 周）后再下结论。

当前仅 37% 订单到期，逾期订单暴露快会高估实验组逾期率，建议 9 月中下旬复核。

附录：完整 PGSQL

模块一：构建 4 批召回用户 + 汇总（到期订单口径）
WITH t7 AS (
    SELECT churn_user_id::bigint AS user_id, ab_group, DATE '2026-08-04' AS recall_date
    FROM wangchuanliang.no_apply_0730_0804_30pct
    UNION ALL SELECT churn_user_id::bigint, ab_group, DATE '2026-08-05' FROM wangchuanliang.no_apply_0731_0805_30pct
    UNION ALL SELECT churn_user_id::bigint, ab_group, DATE '2026-08-06' FROM wangchuanliang.no_apply_0801_0806_30pct
    UNION ALL SELECT churn_user_id::bigint, ab_group, DATE '2026-08-07' FROM wangchuanliang.no_apply_0802_0807_30pct
)
SELECT
    t7.ab_group  AS 分组,
    COUNT(DISTINCT a.serial_id)  AS 到期件数,
    COUNT(DISTINCT a.user_id)    AS 到期人数,
    ROUND(ROUND(SUM(a.repaid_amt_period) - SUM(a.remit_amt_period), 2)
          / NULLIF(ROUND(SUM(a.remit_amt_period), 2), 0) * 100, 2)  AS 盈利率,
    ROUND((SUM(CASE WHEN a.loan_status_code_period = 8 THEN a.remit_amt_period ELSE 0 END) + 0.0)
          / NULLIF(SUM(a.remit_amt_period), 0) * 100, 2)  AS 逾期率_金额,
    ROUND((COUNT(CASE WHEN a.loan_status_code_period = 8 THEN a.serial_id END) + 0.0)
          / NULLIF(COUNT(a.serial_id), 0) * 100, 2)  AS 逾期率_分期,
    ROUND((COUNT(DISTINCT CASE WHEN a.loan_status_code_period = 8 THEN a.serial_id END) + 0.0)
          / NULLIF(COUNT(DISTINCT a.serial_id), 0) * 100, 2)  AS 逾期率_订单
FROM t7
JOIN wangchuanliang.repayment_plan_v2_copy a
  ON a.user_id = t7.user_id AND a.remit_date >= t7.recall_date
WHERE a.is_remit = 1 AND a.due_date < current_date AND a.loan_status_code_period IN (7, 8)
GROUP BY t7.ab_group
ORDER BY t7.ab_group;
模块二：累计提单率
WITH t7 AS (
    SELECT churn_user_id::bigint AS user_id, ab_group, DATE '2026-08-04' AS recall_date
    FROM wangchuanliang.no_apply_0730_0804_30pct
    UNION ALL SELECT churn_user_id::bigint, ab_group, DATE '2026-08-05' FROM wangchuanliang.no_apply_0731_0805_30pct
    UNION ALL SELECT churn_user_id::bigint, ab_group, DATE '2026-08-06' FROM wangchuanliang.no_apply_0801_0806_30pct
    UNION ALL SELECT churn_user_id::bigint, ab_group, DATE '2026-08-07' FROM wangchuanliang.no_apply_0802_0807_30pct
)
SELECT t7.ab_group AS 分组,
       COUNT(DISTINCT t7.user_id) AS 用户数,
       COUNT(DISTINCT CASE WHEN o.serial_id IS NOT NULL THEN t7.user_id END) AS 累计提单用户,
       ROUND(COUNT(DISTINCT CASE WHEN o.serial_id IS NOT NULL THEN t7.user_id END) * 100.0
             / NULLIF(COUNT(DISTINCT t7.user_id), 0), 2) AS 累计提单率
FROM t7
LEFT JOIN wangchuanliang.order_loan_f_v2_copy o
       ON o.user_id = t7.user_id AND o.apply_date >= t7.recall_date
GROUP BY t7.ab_group
ORDER BY t7.ab_group;
模块三：AB 组 × 四周窗口交叉（到期口径）
WITH t7 AS (
    SELECT churn_user_id::bigint AS user_id, ab_group, DATE '2026-08-04' AS recall_date
    FROM wangchuanliang.no_apply_0730_0804_30pct
    UNION ALL SELECT churn_user_id::bigint, ab_group, DATE '2026-08-05' FROM wangchuanliang.no_apply_0731_0805_30pct
    UNION ALL SELECT churn_user_id::bigint, ab_group, DATE '2026-08-06' FROM wangchuanliang.no_apply_0801_0806_30pct
    UNION ALL SELECT churn_user_id::bigint, ab_group, DATE '2026-08-07' FROM wangchuanliang.no_apply_0802_0807_30pct
),
ords AS (
    SELECT t7.ab_group,
           CASE WHEN a.apply_date BETWEEN t7.recall_date AND t7.recall_date + 6 THEN '第一周'
                WHEN a.apply_date BETWEEN t7.recall_date + 7 AND t7.recall_date + 13 THEN '第二周'
                WHEN a.apply_date BETWEEN t7.recall_date + 14 AND t7.recall_date + 20 THEN '第三周'
                ELSE '21天后' END AS win,
           a.serial_id, a.loan_status_code_period, a.remit_amt_period, a.repaid_amt_period
    FROM t7
    JOIN wangchuanliang.repayment_plan_v2_copy a
      ON a.user_id = t7.user_id AND a.remit_date >= t7.recall_date
    WHERE a.is_remit = 1 AND a.due_date < current_date AND a.loan_status_code_period IN (7, 8)
)
SELECT ab_group, win,
       COUNT(DISTINCT serial_id) AS 到期件数,
       ROUND(ROUND(SUM(repaid_amt_period) - SUM(remit_amt_period), 2)
             / NULLIF(ROUND(SUM(remit_amt_period), 2), 0) * 100, 2) AS 盈利率,
       ROUND((SUM(CASE WHEN loan_status_code_period = 8 THEN remit_amt_period ELSE 0 END) + 0.0)
             / NULLIF(SUM(remit_amt_period), 0) * 100, 2) AS 逾期率_金额,
       ROUND((COUNT(DISTINCT CASE WHEN loan_status_code_period = 8 THEN serial_id END) + 0.0)
             / NULLIF(COUNT(DISTINCT serial_id), 0) * 100, 2) AS 逾期率_订单
FROM ords
GROUP BY ab_group, win
ORDER BY ab_group, CASE win WHEN '第一周' THEN 1 WHEN '第二周' THEN 2 WHEN '第三周' THEN 3 ELSE 4 END;
口径说明：4 批 T4 用户合并（召回日 08-04/05/06/07），实验组 7 天 30% 降息券、对照组 3 天 30% 降息券。累计提单率 = 召回后累计提单；盈利率/逾期率为到期订单口径（due_date < current_date，分期级 repayment_plan_v2_copy，仅计 loan_status_code_period ∈ (7,8)）。盈利率 = (Σrepaid_amt_period − Σremit_amt_period) / Σremit_amt_period。
⚠️ 观察期仅约 4 周，放款订单中仅约 37% 已到期，盈利率/逾期率为早期快照，样本小（到期 206/220 件），结论需更长观察期复核。
