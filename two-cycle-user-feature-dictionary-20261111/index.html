01

统计对象与统一范围

统计粒度为统一截止时点A下，每位用户一行。覆盖源数据可用的完整生命周期，以下四项准入条件须在同一快照同时满足。

准入条件统一业务口径
循环贷成功放款恰好2笔截至A，recycle_type=2的成功放款订单数恰好为2。成功放款要求is_remit=1、remit_amt>0，且apply_time ≤ remit_time < A。
最新有效类型的原始获额通过先剔除recycle_type=1，再在类型2、3的全部原始获额中按获额时间、serial_id倒序定位最新一笔，最后判断is_pass1=1。不能先筛通过再选最新。
当前不存在状态8订单用户全部产品当前loan_status_code=8的订单数为0。
当前至少1笔状态5在途订单用户全部产品当前loan_status_code=5的订单数至少为1；不限循环贷，可以有多笔。

业务时区统一为America/Belize；所有源数据使用同一固定快照，发生时间早于A。永久排除用户5101518。实际订单按user_id + serial_id去重，提单次数包含失败、取消及未成功放款的实际提单。

本说明共44项业务特征，分为常规字段4项、第一笔循环贷放款订单19项、第二笔循环贷放款订单21项。用户ID、快照时间、订单编号等关联辅助信息不计入44项。

02

时间锚点与统计窗口

先从用户成功放款的循环贷订单中，按apply_time, serial_id升序编号，依次定位O1、O2；T1、T2取两笔订单各自的提单时间。

符号含义
A / D本次构建固定截止时点A，以及对应的Belize业务日期D。
O1 / T1第一笔成功放款的循环贷订单，以及该笔订单的提单时间。
O2 / T2第二笔成功放款的循环贷订单，以及该笔订单的提单时间。
P1 / P2分别取T1、T2之前已成功放款的全产品最后一笔订单，按remit_time, apply_time, serial_id倒序定位。不存在则为NULL。
C(Oi) / C(Pi)当前循环贷订单Oi、对应上一笔放款订单Pi原始关联通过获额的选定额度，i为1或2。
U(Oi) / U(Pi)对应订单的额度使用率，即各自apply_amt / 选定额度。

阶段与累计窗口

窗口获额时间范围计算方式
第一阶段credit_time ≤ T1第一笔成功放款订单提单及之前，独立20秒去重，次数记N1。
第二阶段T1 < credit_time ≤ T2两笔成功放款循环贷订单的提单时间之间，独立20秒去重，次数记N2。
截至第二笔的累计credit_time ≤ T2截至T2的完整生命周期窗口独立20秒去重，次数记N累计。

第二阶段的起点固定为T1。实际放款时间R1不参与该窗口边界。获额时间恰好等于T1时归第一阶段，恰好等于T2时计入第二阶段。累计窗口单独计算，不能用N1与N2相加替代。

两笔订单的特征均以成功放款订单为锚点；各笔“上一笔放款订单”取全产品最后已放款订单。第一笔循环贷实际提单但未成功放款的订单不替代O1；P2也不强制取O1。

03

通过获额去重与产品识别

获额类型业务含义特征使用规则
recycle_type=1无效获额剔除，不计数、不关联订单获额属性，也不连接20秒去重链。
recycle_type=2循环贷获额循环贷阶段、单/双产品及累计获额次数，仅保留loan_type_code=2 AND is_pass1=1。
recycle_type=3结清续贷获额与循环贷分别识别，不混入循环贷获额次数。作为前序订单获额属性来源时，仍须is_pass1=1。

20秒相邻链去重

先筛循环贷通过获额，再分别切出第一阶段、第二阶段及累计窗口。在每个窗口内，同一用户按credit_time, serial_id排序，相邻通过获额间隔不超过20秒归为一链。每链保留时间最晚一笔，同一时间保留serial_id最大一笔。

相邻链可传递连接：例如第0、15、30秒的三条通过获额归为一链。类型1、类型3及失败获额均不参与循环贷获额去重，也不能连接去重链。

单产品、双产品与订单属性

risk_product按逗号拆分，去首尾空白、空编号及重复编号。不同产品编号恰好1个为单产品，恰好2个为双产品；缺失或3个及以上仍可计入获额总次数，但不计入单、双产品次数。

O1、O2、P1、P2的额度、所选产品账期、息费及是否双产品，按原始订单user_id + serial_id关联有效类型2/3且is_pass1=1的原始获额，要求credit_time ≤ 对应订单apply_time。不因获额20秒去重而替换订单编号。原始获额未匹配、关联冲突或对应产品配置无法唯一确定时，受影响属性为NULL。

账期使用实际选择产品的完整借款期限天数；息费使用所选产品配置total_fee。产品期限须有效、为正整数天，息费率须有效且非负。没有可靠通过获额时，不绕过获额关联直接补取产品属性。

阶段提单率与累计提单率

指标公式分子口径
第一阶段放款订单提单率1 / N1固定为当前第一笔订单对应的1次。
第二阶段放款订单提单率1 / N2固定为当前第二笔订单对应的1次。
截至第二笔的累计提单率截至T2实际循环贷提单订单数 / N累计包含未成功放款的实际循环贷提单，按订单去重；不固定为2，不只匹配获额去重代表编号。

上述分母为0时均为NULL。阶段提单率分子不因其他提单增加；累计提单率按源表公式保留原值，不封顶。

04

额度选择与小数存储

额度字段切换依据关联获额的vir_date，不使用提单日或放款日替代。O1、O2、P1、P2分别按自身关联获额判断。

获额日期与类型首选字段仅首选为NULL时回退
vir_date ≥ 2025-04-01，全部有效类型max_credit_apply_amtmax_risk_credit_amount
vir_date < 2025-04-01，循环贷类型2max_credit_apply_amtmax_risk_credit_amount
vir_date < 2025-04-01，非循环贷有效类型3max_risk_credit_amountmax_credit_apply_amt

首选额度为0或负数时不回退。选定的额度金额保留原始数值；额度使用率仅在选定额度大于0时计算。vir_date缺失、额度缺失或非正时，使用率为NULL，排除该指标的汇总和有效样本量，结果不封顶。

额度、费率与差值

额度使用率 = apply_amt按vir_date选定的额度
额度变化幅度 = C(Oi) − C(Pi)C(Pi)
息费变化幅度 = total_fee(Oi) − total_fee(Pi)total_fee(Pi)

额度使用率变化为U(Oi) − U(Pi)；账期增加天数为本笔完整账期减上笔完整账期。差值可以为负。计算相对变化幅度时，基准额度或基准息费率须大于0；任一输入缺失时，相关差值与比率为NULL。

统一数值保存

字段类型保存方式
次数整数，真实无符合条件事件时为0。
金额数值型小数，保留有效精度。
比例与费率数值型小数，例如80%存0.80、负10%存-0.10、60%息费率存0.60；不乘100，不带百分号。
自然日差与账期整数天；平均相邻提单间隔保留小数天。
是否标志1表示是，0表示否，无法判断为NULL。
缺失与精度NULL不按0填充。数值类型不代表统一强制舍入，计算保留有效精度。
05

常规字段 · 4项

本组4项均截至A统计，使用完整生命周期实际订单；不使用获额20秒去重代替订单去重。

F01整数

用户总提单次数

截至统一截止时点A，用户生命周期内全部产品的实际提单订单数，按user_id与serial_id去重；包含失败、取消和未成功放款的提单。没有符合条件的记录记0，不进行获额20秒去重。

计算COUNT(截至A的全部产品实际提单订单)
F02整数

用户总放款次数

截至A，用户生命周期内全部产品的成功放款订单数，按user_id与serial_id去重。成功放款要求is_remit=1、remit_amt>0，放款时间有效且apply_time≤remit_time<A；没有符合条件的记录记0。

计算COUNT(截至A的全部产品成功放款订单)
F03整数

用户循环贷提单次数

截至A，用户生命周期内recycle_type=2的实际提单订单数，按user_id与serial_id去重；不要求成功放款，可能大于2，不进行获额20秒去重。没有符合条件的记录记0。

计算COUNT(截至A的实际循环贷提单订单)
F04整数

用户循环贷放款次数

截至A，用户生命周期内recycle_type=2且满足成功放款条件的订单数。目标用户该值必须恰好为2；该条件不代表循环贷提单总数也等于2。

计算COUNT(截至A的循环贷成功放款订单)=2
06

第1笔循环贷放款订单 · 19项

本组19项以O1为锚点。获额次数使用credit_time ≤ T1第一阶段；额度、账期和息费分别比较O1与P1；提单间隔使用截至T1的全产品实际提单历史。

获额订单

F05整数

第一阶段循环贷获额次数

第一阶段取credit_time≤T1、loan_type_code=2、recycle_type=2且is_pass1=1的循环贷获额，先切窗，再按该用户窗内20秒相邻链独立去重，统计保留代表记录的事件数N1。类型1、类型3及未通过记录不参与计数或连接去重链；没有合格事件记0。

计算N1=COUNT(第一阶段通过循环贷获额的20秒去重代表记录)
F06整数

第一阶段单产品获额次数

在第一阶段通过循环贷获额的20秒去重代表记录中，risk_product按逗号拆分、去空白、去空项及去重后，不同产品编号恰好为1个的事件数。产品缺失或不同编号数不等于1的事件不计入本项；没有合格事件记0。

计算COUNT(第一阶段代表记录中清洗后不同产品数=1)
F07整数

第一阶段双产品获额次数

在第一阶段通过循环贷获额的20秒去重代表记录中，清洗后不同产品编号恰好为2个的事件数。产品缺失、只有1个或有3个及以上的事件不计入本项；没有合格事件记0。

计算COUNT(第一阶段代表记录中清洗后不同产品数=2)
F080或1

本笔是否双产品获额提单

以第一笔循环贷成功放款订单O1的user_id+serial_id关联该笔订单原始有效通过获额，不用去重后其他订单的代表记录替换。清洗后不同可选产品恰好2个记1，恰好1个记0；获额未匹配、产品缺失或超过2个记NULL。

计算可选产品数=2→1；可选产品数=1→0；其余→NULL
F09小数

第一阶段放款订单提单率

按文件定义，以本笔成功放款订单对应的1次作为固定分子，除以第一阶段通过循环贷获额经20秒去重后的次数N1。阶段内其他提单不增加该分子；N1=0时记NULL。按小数比例保存。

额度变化

F12小数

用户生命周期提单间隔

07

第2笔循环贷放款订单 · 21项

本组21项以O2为锚点。阶段获额使用T1 < credit_time ≤ T2；额度、账期和息费分别比较O2与P2；最后两项在截至T2的完整累计窗口计算。

获额订单

F24整数

第二阶段循环贷获额次数

第二阶段严格取T1<credit_time≤T2、loan_type_code=2、recycle_type=2且is_pass1=1的循环贷获额，先切窗，再按该用户窗内20秒相邻链独立去重，统计保留代表记录的事件数N2。起点使用O1的提单时间T1，不使用实际放款时间R1；无合格事件记0。类型1、类型3及未通过记录不计数、不连接去重链。

计算N2=COUNT((T1,T2]通过循环贷获额的20秒去重代表记录)
F25整数

第二阶段单产品获额次数

在T1<credit_time≤T2窗口内，通过循环贷获额独立20秒去重后的代表记录中，risk_product清洗后不同产品编号恰好为1个的事件数。产品缺失或不同编号数不等于1的事件不计入本项；没有合格事件记0。
