流失7天以上用户｜405风险再评级模型 V1 开发方案

报告生成：2026年10月9日 · 业务日期：America/Belize · 用户级数据仅本地保存

一、目标与交付

目标：在405实时评分基础上，识别流失≥7天用户再次借款时被原评分低估的风险；不替换原模型，不混入363评分。

1. 还原流失周期
结清后通过获额为起点
2. 取得实时评分
观测前最近获额405分
3. 增加生命周期信息
流失、贷后、App行为
4. 验证再评级效果
时间外测试与分群对照

输出开发方案、特征字典、可复跑取数SQL、训练模型、测试结果、预测明细。仅方案和汇总验证报告发布到网页。

二、三个时间点必须分开

时间点定义用途
流失起点 t_anchor整笔结清后当天，获额通过is_pass1=1、续贷、recycle_type=3，且结清时无其他在贷。通过记录先按订单保留最新，再做20秒链式去重。累计流失天数；重新获额不重置。
观测时刻 t_obs历史样本：该流失周期第一次再次提单的时刻，使用提单前可得信息；实时预测：数据完整截止日之后的00:00快照。所有特征的时间上限。
评分获额 t_scoret_obs之前最近一次获额记录（同时间按serial_id较大取）；用其serial_id匹配405分。最新获额缺分不回退旧分。当前资质、评分年龄、是否重新获额。

15天内可能沿用原评分；超过有效期再次提单通常重新获额。要解决的是“最新评分对长期流失风险仍可能低估”，不是简单把起点旧评分加上流失天数。

anchor = 结清后通过的type=3获额事件
next_apply = anchor之后、下一anchor之前的首次用户提单（不限serial）
obs = next_apply.time  # 训练的提单前风险快照
churn_days = DATE(obs) - DATE(anchor.time)
latest_offer = 最近一条 offer.time <= obs，按时间/订单号倒序
score405 = model_result[latest_offer.serial_id].405
如果最新评分缺失：剔除；如果churn_days < 7：不进入主模型
如果next_apply未成功放款或标签未成熟：不进入监督训练

三、样本与风险标签

  • 训练起始：再次提单日期≥2025-07-01；历史记录不限于此日期以后，以还原生命周期。
  • 一条样本为一个流失周期的首次再次提单；一笔订单最多一条样本。成功放款is_remit=1、remit_amt>0才有可验证的贷后标签。
  • 主标签：整笔订单到期后D7仍未结清。repaid_date有效且≤due_date+7为0，否则为1；必须due_date+7已完整观察。不是“今天是否loan_status_code=8”，也不是405原始训练标签的宣称复现。
  • 辅助风险口径：整笔订单是否晚于due_date结清，用来展示风险差异，不与主标签混称。
  • 历史未提单者、拒绝放款者及未成熟订单的风险未知，不能作为正常用户训练。实时流失名单能输出风险排序，但预测值只对与历史已放款群体相近的人群有经验支持。

四、405分数区间与用户等级

只用训练段每个用户最近一次有效评分，一人一次，从高分到低分划分；相同分数不强行拆组，实际人数占比可能偏离目标。区间固定用于后续月份。

五、特征开发：按生命周期，而非堆数量

特征组细分时点约束
当前405与流失405分、流失天数/分段、评分年龄、重获额次数、历史405变化、当前额度及对上一笔变化最近获额≤观测；缺最新分排除，不用平均/最高分替代。
历史借还成功放款次数、结清次数、还款速度、提前结清次数/比例、历史已成熟D7风险、件均、账期、息费、额度使用率放款和结清必须已发生；未走完D7不进入历史风险分母。
近期变化最近30/90天申请与借还、距上次行为天数、重获额、上一笔与历史均值差异不使用当前待预测订单的金额、利息、结清或最终状态。
App实际行为过去7/30/90天活跃日、事件、进提单页、金额/期次切换、还款计划、确认、活跃/提单页停留日聚合数据只使用观测日前的完整日期，不混入当天结果。
非还款日App与实际行为完全平行保留，另含非还款活跃占比、强度和趋势实际还款日由还款流水确认；不是到期日，也不是仅结清日。

0额度使用率标缺失，超过100%保留；没有历史行为记0，有数据源不覆盖时标记为缺失，不把未知当0。基准405不使用363或其他模型分。

六、训练、校准与测试

阶段计划时间规则
训练2025-07至2026-05标签截至2026-06-01前成熟，避免训练看到验证期的未来还款。
调参验证2026-06标签截至2026-07-01前成熟；有限网格调参，按AUC选择。
独立概率校准2026-07标签截至2026-08-01前成熟；不用于挑参数。
时间外测试2026-08至最新完整数据只纳入已经D7成熟的订单；最近月份为成熟子样本，展示覆盖。

同一用户可跨月份，符合存量用户的实际部署；另报告测试新用户表现，并用用户聚类自助法评估增益区间，不把事件当作独立用户。

  • 对照1：原始405排序（高分低风险，风险排序用负405）；对照2：405单变量概率模型。
  • 消融：405+流失变量 → 405+生命周期 → 405+生命周期+实际及非还款日App。
  • 指标：AUC、KS、AP、Log loss、Brier、校准分组、风险最高20%的坏账捕获率/坏账率；另看高优/优质长流失用户是否被识别。
  • 模型候选：逻辑回归、直方图梯度提升树。选择与校准仅用验证/校准段，测试不参与反复调参。

七、验收与使用边界

  • 检查起点类型、20秒去重、首次提单归属、评分是否来自最近获额、特征是否早于观测、标签是否成熟以及重复订单。
  • model_result_copy没有评分生成/更新时间字段；能验证获额时点，但无法独立证明该行从未被后来更新。历史回放结果属于有此数据限制的离线验证，上线前应落盘不可变评分快照。
  • 按现有已放款样本训练，存在放款选择偏差；不能证明被拒绝/未提单者的真实逾期风险，也不直接自动拒贷或提额。
  • 如果时间外增益有限或不稳定，保留405基线并如实报告，不把增加特征视为必然提升。
  • 先影子运行、检查月度校准与风险，再由风控设定策略阈值。模型风险等级不等同于审批权限。
