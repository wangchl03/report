一、核心结论

规模增长｜循环贷在续贷中的权重上升

2026年1月至9月，循环贷成功放款从12,460笔增至29,740笔，占续贷成功放款的比例从39.51%升至59.56%；占续贷放款本金的比例从46.24%升至69.34%。增长主要来自活跃借款用户基盘扩大，并伴随老组借款频次上升。

转化承压｜更多获额没有变成提单

按独立获额订单号，1月至9月当日提单率从37.26%降至26.53%；15日内从59.40%降至51.28%。更长窗口没有补回全部下降，且旧获额通常会被后续结清提前覆盖。

收益风险｜盈利额贡献不等于效率领先

8月近完整成熟样本中，循环贷实际回款盈利率13.20%，低于结清续贷的14.70%；当前整笔逾期率37.20%，高于对照的33.23%。更大的投放本金带来更多盈利额，但不能据此证明循环贷模式更优。

本报告为观察性经营分析，不把“循环贷占比上升”解释成盈利改善的因果原因。盈利额尚未扣营销、资金和运营成本；9月金融质量只覆盖部分成熟订单，10月为截至取数时的部分月份。

二、统计口径与业务链路

结清某一期／整笔订单→获额通过且类型2→产生可提单获额订单号→同订单号提单→成功放款与贷后观察

获额与提单

分母为 is_pass1=1 AND recycle_type=2 的获额订单，同一 serial_id 保留最新获额记录。主表不合并不同订单号；20秒批次去重只作对照。分子按相同 serial_id 的首次提单，不要求成功放款，不把用户通过其他获额订单的提单补回旧订单。

D1、D2为单日；D3累计D0—D3，D7累计D0—D7；15日内沿用循环贷D0—D14自然日有效期。提单率保留未满观察窗口订单，代表截至当前已观察结果。

放款、盈利与风险

成功放款要求 is_remit=1 AND remit_amt>0，按成功放款月份分组。循环贷订单占比＝循环贷放款订单数÷全部loan_type='reloan'续贷放款订单数；循环贷本金占比＝循环贷放款本金÷全部续贷放款本金。首贷不进入这两个分母；标签未知但明确为续贷的订单仍计入续贷分母。盈利与逾期使用 due_date < 业务日期−7 的同一批成熟整笔订单；样本最晚到期日为。

规模、金额、件均与合同息费用全量放款订单。类型2为循环贷，类型3为结清续贷；金额均为墨西哥比索MXN。实际回款使用订单还款流水 repayment_record_copy.amount；账面回款使用订单表 repaid_amt。

口径伪代码｜默认折叠
获额主样本 = 通过获额 AND recycle_type=2
同serial_id保留最新获额记录
首次提单 = 订单表中同serial_id的最早提单
自然日差 = 首次提单日期 − 获额日期
提单率(window) = window内提单获额订单数 / 获额订单数
20秒对照 = 在主样本上按用户相邻≤20秒链式分批，每批取最晚时间、最大订单号

获额可用窗口终点 = min(下一次分期或整笔结清，获额日期+15天00:00)
可用时长 = 窗口终点 − 获额时刻
已提单的实际存续 = 首次提单时刻 − 获额时刻
仍未走完可用窗口者 = 右删失，单列、不计完整窗口时长分母

成功放款样本 = is_remit=1 AND remit_amt>0
续贷放款分母 = 成功放款样本 AND loan_type='reloan'（首贷排除）
循环贷订单占比 = 循环贷成功放款订单数 / 全部续贷成功放款订单数
循环贷本金占比 = 循环贷放款本金 / 全部续贷放款本金
成熟贷后样本 = due_date < 业务当前日期−7
实际回款盈利率 = (SUM(实际到账流水) − SUM(放款本金)) / SUM(放款本金)
账面回款盈利率 = (SUM(repaid_amt) − SUM(放款本金)) / SUM(放款本金)
D7实际回款盈利率 = (SUM(到账日期≤due_date+7的流水) − SUM(放款本金)) / SUM(放款本金)
当前整笔逾期率 = 当前loan_status_code=8订单数 / 成熟订单数
D7整笔逾期率 = 结清日无效或晚于due_date+7订单数 / 成熟订单数

用户生命周期 = 全量可观测历史首次循环贷成功放款起的成功放款序列
主用户样本 = 2025-07-01至取数时曾有循环贷成功放款的用户
转结清续贷须核验：循环贷整笔结清时间≤首笔后续type3订单提单时间
静默用户 = 最后成功放款距取数时≥15/30/60天且无新增成功放款
T0衔接 = 单独复用严格T0事件母表，不替代循环贷获额订单分母

各模块快照和统计单位不同：获额月用于提单，放款月用于经营质量，结清月用于节奏和T0衔接。生命周期按用户，逾期率按订单；“用户至少一笔逾期”不能等同“订单逾期率”。当前T0衔接与增长来源采用既有2026年1月—10月13日已核验统计。

三、供给与放款：循环贷在续贷经营中的权重上升

续贷成功放款数量与结构

循环贷占续贷：订单占比与本金占比

本节两个占比分母均只含续贷（loan_type=reloan），不含首贷。续贷总数＝循环贷＋结清续贷＋标签未知续贷，使用全部成功放款订单，不受成熟度筛选影响。仅修订占比分母，其他章节的原始订单数、提单、盈利及逾期结果保持原快照不变。

借款次数结构：6次及以上占比抬升

1月到9月，循环贷放款中第2次贷款占比从33.93%降至21.38%，第6次及以上从23.30%升至39.01%。第2次循环贷的绝对数量仍由4,228增至6,358笔，不能把占比降低理解为数量减少。

放款次数取当前已成功放款订单的 remit_succ_rnb，不是尚未提单获额订单的次数，也不是触发结清订单的次数。首贷不属于循环贷；源表已核验循环贷次数小于2的放款订单为0。

四、提单转化：订单使用率下降，延后提单补偿有限

首次提单时点构成

窗口延长的增量

全期间15日内首次提单的订单中，98.86%已在D0—D7内提单。2026年1月至9月，当日提单率下降10.73pp，15日内下降8.12pp；不能只用“用户晚几天提单”解释全部下降。

主口径422,895笔获额，对照379,448笔。20秒规则合并的43,447笔均未命中同订单号提单，两套分子完全相同。独立订单衡量获额订单使用，批次口径衡量自动获额机会转化，两者不能混用。9月末及10月尚未完整观察；66笔超过15自然日的同serial提单单列，不纳入15日率。

五、有效时长：多数旧获额并没有完整15天机会

获额月份 × 有效自然日分布

未提单订单的实际结果

重新获额证据与例外

完整观察窗口平均5.21天，其中83.63%在D0—D7内结束；按业务规则，91.62%因下一次分期或整笔结清提前结束。6—7日是主要终点，与分期还款节奏吻合，但不能把这种时序一致性当作政策因果证明。

有效时长沿用20秒去重样本379,448笔，与独立serial主提单表分母不同。可用窗口是“如果尚未使用，能保留到何时”；已提单订单的等待时长另算。10月未完整窗口8,464笔，已结束样本偏向短窗口，其3.01天均值不能直接解释为10月整体变短。

此处按用户提供的“下一次结清触发覆盖”规则推定窗口终点。130,408笔未提单覆盖订单中，126,721笔在下一次结清20秒内出现新获额，3,659笔为24小时内延迟获额，28笔未取得24小时内新获额证据。104笔同serial在理论终点后提单已单列；这是理论有效窗口与实际提单匹配的核验差异。

六、增长来源：用户基盘扩大为主，频次增加为辅

新、老循环贷借款用户及放款量

1月到9月放款增长的数量分解

循环贷放款新增17,280笔中，新循环贷借款组贡献7,085笔（41.0%），动态老组贡献10,195笔（59.0%）。将放款数拆为活跃借款用户数×人均借款频次，用户数因素贡献80.37%，频次因素贡献19.63%。这是算术分解，不是独立识别出的政策效果。

动态老组的人均循环贷放款由1.97笔增至2.68笔；但固定“2026年前已借过循环贷”的55,917人中，月活跃借款人数从1,904降至192。因此，老组增长主要是新用户逐渐累积进入老组，不能概括为所有老用户都被重新激活。

结清节奏没有加快

循环贷当月已整笔结清样本中，实际持有天数由14.58升至16.92，提前结清占比由82.27%降至71.27%，合同账期约24天基本稳定。现有证据不支持“提前结清更快”是规模增长的主要解释。

新资格采用全量历史首次可观测type2获额通过记录，不是官方资格开通日志。“老组”是动态月度分类；结清节奏分母为当月已结清订单，不是到期订单，不能直接替代提前结清政策收益评估。

七、收益与风险：需要按同月、同借款次数对照

风险 × 盈利 × 成熟放款规模

同月循环贷与结清续贷

月份 × 借款次数：多维盈利风险矩阵

8月｜盈利额主要由规模支撑

循环贷实际回款盈利额1,275.75万MXN，结清续贷767.44万MXN。循环贷投入本金更多，盈利额贡献更大，但资本回报率低1.50pp、当前订单逾期率高3.96pp。

第4次贷款｜差距需要优先核查

8月该档循环贷实际盈利率6.01%，结清续贷16.36%，差−10.35pp；当前逾期率分别40.14%、31.61%。这是客群对照，不证明循环贷标签造成差距。

6次及以上｜相对接近，不代表无风险

8月该档循环贷实际盈利率19.10%，对照19.54%；当前逾期率29.47%、28.06%。其收益风险相对其他循环贷次数档更好，但仍需审查产品、额度和资格选择因素。

8月成熟覆盖率：循环贷99.99%、结清续贷98.89%，属于近完整样本，不是严格100%成熟月。9月仅40.36%、50.82%；不可把9月样本的盈利率直接当作9月全量放款结论。全量规模不筛成熟，盈利和风险必须筛同一成熟订单。

当前回款包含到期后催回，固定D7回款仅到due_date+7，二者不能混用。当前状态8与“曾在D7逾期”也不是同一指标。当前真实盈利仅指实际现金回款减放款本金，仍不是扣除获客、资金与运营成本的净利润。

八、用户生命周期：重复循环、转续贷和静默退出

连续循环贷静默用户的风险状态

只借一笔与持续循环不能混为一谈

主样本91,154人中，60,098人首笔循环贷后所有观察到的放款均为循环贷，其中28,698人只有一笔，实际重复循环的为31,400人。已确认循环贷结清后转结清续贷的30,597人中，12,540人又回到循环贷，占40.98%。

“30天没有新成功放款”不等于永久停止借款。连续循环贷且静默30天的49,150人中，85.56%当前至少有一笔整笔状态8订单；这不是所有循环贷订单的逾期率。风险分类范围为首次循环贷及之后放款订单，0逾期天数不算逾期。

资格取消规则：历史记录存在反例，需核验恢复与版本

主样本中3,327人在分期逾期发生日之后仍出现新的循环贷获额通过并成功放款记录。不能强行把这些真实记录删掉来满足“曾逾期后永久不能循环贷”的假设；应核查是否为还清后恢复、历史政策版本、标签口径或日期重建误差。

分期逾期发生日以due_date_period+1重建到日期，同日先后顺序另列，不冒充精确事件时刻。循环贷转结清续贷须证实循环贷整笔结清不晚于后续type3提单；未证实的309名用户与其他标签150人合计459人，单独保留。

九、T0衔接：循环贷结清不一定使用户清空在途订单

循环贷整笔结清后的衔接

非循环贷整笔结清后的衔接

1月到9月，循环贷整笔结清后“没有其他在途订单”的比例由31.87%降至21.61%；非循环贷由81.53%降至72.28%。因此，循环贷放款增长不应被预期为同幅度的T0事件增长，大多数循环贷结清时仍有其他在途订单。

非循环贷整笔结清量由25,181增至29,226，没有下降；清零场景中的结清续贷获额通过比例仅由86.20%降至85.69%。进入T0的结构变化更集中在“是否清空在途”，而不是获额通过率的大幅下降。

本节使用既有2026年1月—10月13日统计。漏斗前段按结清订单／清零场景，最后提到的T0“事件数”可高于T0结清订单数，不能在一条订单漏斗中强行混成同一单位。这里没有重新定义T0或扩大其分母。

十、经营动作与结论边界

转化管理｜围绕有效订单前置触达

依据：83.63%的完整可用窗口在D0—D7结束，D7之后新增提单有限。

动作：优先评估当天至前3天的页面引导和触达时机。每次触达先核验当前有效获额订单号，避免向被覆盖或过期订单投放优惠。

验证：采用同资格随机对照，记录触达、当前serial、提单、盈利与风险，不能仅比较被选择的已提单用户。

经营效率｜优先核查第4次循环贷

依据：8月同次数对照中，第4次循环贷盈利差−10.35pp、当前逾期差+8.53pp。

动作：进一步拆解该档的产品、账期、额度与当时风控资质。以成熟实际回款和固定D7风险共同评估，不单凭订单量增加判断成功。

边界：当前未扣市场、资金和运营成本，也未消除资格选择差异；不能直接据此改变授信资格或认定降价可改善风险。

用户管理｜区分风险受限与主动静默

依据：连续循环贷静默30天用户以当前状态8为主，真正全部结清且无历史分期逾期的为3,139人。

动作：将风险受限、历史逾期已结清、正常清偿静默分开跟踪。核验循环贷资格取消／恢复规则，不把所有无新放款用户都当成同一类召回对象。

验证：分别观察资格、提单、放款、回款与贷后结果，保留未成熟样本标记。

总体判断：循环贷已经成为更重要的放款和盈利额来源，但获额转化在下降，收益风险效率并未全面领先。下一步重点应是有效窗口内转化、薄弱借款次数档和资格规则核验，而不是只追求循环贷占比继续上升。
