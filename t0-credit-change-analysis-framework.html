T0额度变化对当天提单率影响
分析框架与实施规划

规律识别 → 机制解释 → 用户级决策引擎｜汇报对齐版｜2026-09-24

课题目标：先识别哪些额度策略导致T0当天提单率变化，再解释额度变化影响用户行为的传导路径，最终将规律和机制转化为用户级触达决策，提高增量提单率，而不是只总结历史相关性。

一、三层分析主线

第一层

规律层 当前重点

以“用户 × T0事件”为单位，回答额度降低、不变、增加及不同额度迁移档，分别如何影响当天提单率。

解决的问题

什么策略、什么客群、什么时间出现了异动；谁拉低或抬高了整体提单率。

核心输出

异动额度档、贡献度、规律性结论及第二层重点深挖客群。

→
第二层

机制层

基于App埋点还原获额后进页、调整金额/期次、查看费用、确认提单的行为漏斗。

解决的问题

额度变化为什么影响提单；影响发生在进页、决策还是确认环节。

核心输出

“额度变化 → 用户行为 → 提单结果”的传导链路。

→
第三层

生命周期与决策层

以用户为单位整合历次T0、额度变化、提单和行为经历，预测不同策略对单个用户的增量效果。

解决的问题

当前这个用户是否需要触达、采用什么策略、何时触达。

核心输出

用户级策略、预计增量和可供自动脚本执行的决策结果。

二、统一统计口径

统计时间2026-01-01至2026-09-20；9月为1—20日部分月份，单独标记。
基础样本上一笔订单已结清、结清时0在贷、随后T0获额通过。当前获额时下一笔尚未提单。
分析单位用户 × T0事件。同一用户不同时间发生多次T0，分别计入；不按月只保留一个用户。
20秒去重同一用户相邻获额时间差≤20秒归为同一批；批内按“获额时间倒序、订单编号倒序”取第一笔。
额度变化当前T0获额 − 刚结清订单对应的上一笔获额。小于0为降额，等于0为额度不变，大于0为提额。
当天提单提单时间必须满足 apply_time ≥ vir_time 且发生在同一自然日；同次T0当天多笔提单只记一次。
提单率
T0当天提单率 = 获额通过后当天发生提单的T0事件数 ÷ 全部符合条件的T0事件数
事件归属同一用户同日存在多个独立T0事件时，将提单分配给其发生前最近的一次T0事件，避免重复计算。

三、第一层：规律分析的实施步骤

第一阶段先完成数据归因，明确“哪里发生了问题”，再把重点客群交给第二层分析行为机制。

步骤1

全体T0当天提单率趋势

先统计整体事件数、用户数、当天提单数和提单率，观察1月至9月20日的月度趋势、环比变化和异常月份。

步骤2

拆分降额、额度不变、提额三类

比较三类事件的规模、占比和月度提单率，判断整体变化来自哪一类用户自身表现下降，还是低提单率类别占比上升。

步骤3

拆解额度变化幅度

按变化金额和变化率分档，分析不同降额/提额幅度对当天提单率的影响，识别是否存在明显阈值或非线性关系。

步骤4

拆解准确额度迁移路径

分析2,000→3,000、3,000→4,000、3,000→3,000、4,000→3,000等具体迁移档，找出提单率下降最大、样本量最大和对整体下降贡献最大的档位。

步骤5

完成结构与档内贡献归因

将整体变化拆分为“档内提单率变化”和“样本结构变化”，避免把占比变化误判为策略效果。

整体提单率 = Σ（各额度档事件占比 × 各额度档当天提单率）
步骤6

控制客群差异

以额度不变为参照，在相同月份、上一笔额度、借款次数、上一笔使用率和用户资质内比较降额/不变/提额，减少客群结构对结论的干扰。

步骤7

形成规律结论和深挖清单

区分规律性原因与小样本波动，输出需要进入第二层埋点分析的重点额度档、月份和用户群体。

四、第一层重点回答的问题

趋势 整体为什么下降

  • 从哪个月份开始异动？
  • 降额、不变、提额哪一类贡献最大？
  • 是该类自身提单率下降，还是该类占比变化？

策略 哪个额度档最关键

  • 哪个准确额度迁移档下降最多？
  • 哪个档样本量大且持续下降？
  • 是否存在降额/提额幅度阈值？

客群 哪类用户产生异动

  • 不同借款次数、历史使用率和资质是否不同？
  • 相同上一笔额度下，降额/不变/提额差异多大？
  • 哪些结论跨月稳定、可复用？

归因 是否真是额度因素

  • 原始差异有多少来自客群不同？
  • 标准化后额度变化仍有多大影响？
  • 哪些结论只能视为相关性，需实验验证？

五、第二层：行为机制分析

第二层只在第一层确定的异动客群中展开。所有行为必须发生在T0获额之后：event.create_time ≥ vir_time。

T0获额 → 进入借款页 → 切换金额/期次 → 查看合同/还款计划 → 选择借款原因 → 确认提单 → 成功提单
  • 判断额度变化影响的是进页意愿，还是进页后的决策与确认。
  • 比较降额、不变、提额及重点额度迁移档的行为漏斗和流失节点。
  • 形成可解释的传导结论：额度变化如何改变用户行为，最终影响当天提单率。

六、第三层：生命周期与用户级决策引擎

用户生命周期画像

  • 历次T0结清续贷及额度变化序列
  • 历史提额、降额、不变后的提单表现
  • 最近1—3次提单和页面行为
  • 连续提单/未提单、降额敏感度和提额响应度

策略响应预测

  • 自然提单概率
  • 提醒、提额、额度恢复或发券后的预测概率
  • 各策略预计增量及成本收益
  • 推荐动作、触达时间、渠道和置信度
最终形态：将用户当前状态和历史生命周期画像输入决策引擎，输出 NO_ACTION / REMIND / CREDIT_RECOVERY / CREDIT_INCREASE / COUPON / DELAY_TOUCH 等可执行策略，由脚本自动触达，并持续回收结果更新模型。

七、阶段规划与当前重点

阶段一：规律层

现在先做

  • 完成统一事件母表
  • 总体及三类月度趋势
  • 幅度档和准确迁移档
  • 结构/档内贡献拆解
  • 形成异动客群清单

阶段二：机制层

在阶段一结论后启动

  • 确定重点人群与月份
  • 构建App行为漏斗
  • 识别关键流失节点
  • 验证额度影响路径

阶段三：决策层

在规律与机制稳定后启动

  • 建立用户生命周期档案
  • 训练策略响应模型
  • 输出用户级动作
  • 小流量实验与自动触达

八、第一阶段交付标准

数据与报告

  • 完整分析报告及可视化
  • 总体、三类、幅度档、准确迁移档明细
  • 月度归因及贡献度表
  • 可复现全部指标的完整PGSQL

结论与下一步输入

  • 整体提单率异动的主要贡献来源
  • Top异动额度策略和用户群体
  • 规律性结论与小样本异常的区分
  • 第二层需要重点验证的行为假设清单
分析边界：第一层主要完成历史数据归因和规律识别，不能仅凭相关性证明额度变化的因果效果。因果判断需要在第二、三阶段通过同层匹配、时间外验证和随机对照实验逐步确认。

本规划用于课题汇报与团队口径对齐。当前优先完成第一层规律分析。
