四、成熟月份与显示规则

成熟判断以首贷月份最后一天为基准，而不是该渠道实际最后一笔订单日期。这样同一个首贷月份在所有渠道上使用完全一致的成熟边界。

data_date = CURRENT_DATE - 1
month_end = 首贷申请月最后一天

is_mature =
    month_end + window_day <= data_date
    AND apply_month <= 当前月月初 - 2个月

结果：当前月、上个月的生命周期指标始终不展示；
      首贷人数、金额、件均、CPS仍展示到 data_date。

示例：运行日为6月15日，data_date为6月14日

首贷月份基础指标30天生命周期60天生命周期原因
6月展示6月1—14日空白空白当前月只展示基础指标。
5月展示完整5月空白空白业务规则明确排除上个月生命周期。
4月展示展示空白4月30日+30天已成熟；+60天尚未成熟。
3月及以前展示按成熟度展示按成熟度展示各窗口独立判断。
禁止做法：不能把 is_mature=1 设置为整个 Dashboard 的全局筛选器，否则本月和上个月的首贷人数、首贷金额、件均、CPS也会一起消失。

五、指标计算逻辑

类型指标计算公式成熟限制
基础首贷人数首贷成功放款用户去重数否
基础首贷放款金额首贷成功放款金额（USD）否
基础首贷件均首贷放款金额 / 首贷人数否
基础CPS市场成本（USD）/ 首贷人数否
生命周期利润窗口内实际还款 − 窗口内整笔到期订单放款是
生命周期APPU生命周期利润 / 首贷人数是
生命周期盈利率生命周期利润 / 到期整笔订单放款金额是
生命周期件均到期整笔订单放款金额 / 到期整笔订单数是
生命周期整笔订单逾期率逾期整笔订单数 / 到期整笔订单数是
生命周期分期金额逾期率窗口截止日未结清分期本金 / 到期整笔订单放款金额是
生命周期平均期限到期整笔订单 loan_day 合计 / 到期整笔订单数是
生命周期平均息费率到期整笔订单息费合计 / 到期整笔订单放款金额是
分母为0时返回 NULL：空白代表当前组合没有可计算样本；不应显示0%，避免把“无样本”误读成“表现为零”。

计算伪代码

FOR 每个首贷月份、渠道:
    计算基础指标：首贷人数、首贷金额、市场成本

    FOR window_day IN (30,60,...,360):
        window_end = 首贷申请时点 + window_day
        纳入窗口内提单、成功放款且整笔已到期的订单
        还款 = 从订单提单日到 window_end 的实际到账流水
        利润 = 还款 - 放款
        逾期 = window_end 时任一期仍未结清
        判断该首贷月份是否完全成熟

        IF 未成熟:
            生命周期原子字段 = NULL
        ELSE:
            写入各项分子、分母

    基础指标只在 window_day=30 的行参与 Tableau 汇总

六、Tableau 具体实现

连接正式表连接 wangchuanliang.rpt_firstloan_channel_lifecycle；不要直接连接暂存表。
创建 Extract发布数据源时嵌入数据库凭据，设置每日完整刷新；报表表体量小，不需要明细级增量。
建立基础指标工作表行放月份、渠道；列放首贷人数、金额、件均、CPS；字段内部限定 is_base_row=1。
建立生命周期工作表行同左表；列先放 Measure Names，再放观察窗口；每个指标按30—360天横向展开。
拼接 Dashboard两个工作表放入同一水平容器，隐藏右表重复行标题，统一行高、排序、汇总与筛选器。
发布与订阅Tableau Server在数据库刷新完成后再刷新Extract；启用失败邮件通知。

核心计算字段

基础指标计算字段
// 观察窗口
STR([window_day]) + "天"

// 首贷人数
SUM(IF [is_base_row] = 1 THEN [first_loan_user_count] END)

// 首贷放款金额
SUM(IF [is_base_row] = 1 THEN [first_loan_amt_usd] END)

// 首贷件均
IF [首贷人数] = 0 THEN NULL
ELSE [首贷放款金额] / [首贷人数]
END

// 市场成本
SUM(IF [is_base_row] = 1 THEN [marketing_cost_usd] END)

// CPS
IF [首贷人数] = 0 THEN NULL
ELSE [市场成本] / [首贷人数]
END
生命周期计算字段
// 利润
SUM(IF [is_mature] = 1 THEN [profit_amt_usd] END)

// APPU
IF SUM(IF [is_mature] = 1 THEN [first_loan_user_count] END) = 0 THEN NULL
ELSE
    SUM(IF [is_mature] = 1 THEN [profit_amt_usd] END)
    /
    SUM(IF [is_mature] = 1 THEN [first_loan_user_count] END)
END

// 盈利率
IF SUM(IF [is_mature] = 1 THEN [due_whole_order_remit_amt_usd] END) = 0 THEN NULL
ELSE
    SUM(IF [is_mature] = 1 THEN [profit_amt_usd] END)
    /
    SUM(IF [is_mature] = 1 THEN [due_whole_order_remit_amt_usd] END)
END

// 生命周期件均
IF SUM(IF [is_mature] = 1 THEN [due_whole_order_count] END) = 0 THEN NULL
ELSE
    SUM(IF [is_mature] = 1 THEN [due_whole_order_remit_amt_usd] END)
    /
    SUM(IF [is_mature] = 1 THEN [due_whole_order_count] END)
END

// 整笔订单逾期率
IF SUM(IF [is_mature] = 1 THEN [due_whole_order_count] END) = 0 THEN NULL
ELSE
    SUM(IF [is_mature] = 1 THEN [overdue_whole_order_count] END)
    /
    SUM(IF [is_mature] = 1 THEN [due_whole_order_count] END)
END

// 分期金额逾期率
IF SUM(IF [is_mature] = 1 THEN [due_whole_order_remit_amt_usd] END) = 0 THEN NULL
ELSE
    SUM(IF [is_mature] = 1 THEN [overdue_term_remit_amt_usd] END)
    /
    SUM(IF [is_mature] = 1 THEN [due_whole_order_remit_amt_usd] END)
END

// 平均期限
IF SUM(IF [is_mature] = 1 THEN [due_whole_order_count] END) = 0 THEN NULL
ELSE
    SUM(IF [is_mature] = 1 THEN [whole_order_loan_days_sum] END)
    /
    SUM(IF [is_mature] = 1 THEN [due_whole_order_count] END)
END

// 平均息费率
IF SUM(IF [is_mature] = 1 THEN [due_whole_order_remit_amt_usd] END) = 0 THEN NULL
ELSE
    SUM(IF [is_mature] = 1 THEN [whole_order_interest_amt_usd] END)
    /
    SUM(IF [is_mature] = 1 THEN [due_whole_order_remit_amt_usd] END)
END

生命周期矩阵的字段摆放

  1. 行：apply_month、channel_catgy。
  2. 列：先放“度量名称（Measure Names）”，再放离散字段“观察窗口”。顺序不能反。
  3. 标记/文本：放“度量值（Measure Values）”，只保留利润、APPU、盈利率、件均、逾期率、平均期限、平均息费率。
  4. 空白处理：不要过滤 NULL；打开“显示空行”，让未成熟窗口保持空白而不是消失或显示0。
  5. 筛选同步：月份、渠道筛选器应用到两个工作表；is_mature不做全局筛选。

月度汇总与渠道小计

SQL无需再生成一套“全渠道月度汇总行”。Tableau在月份层级开启小计或移除渠道维度，即可汇总全部渠道。金额、人数和订单数直接求和；件均、CPS、APPU、盈利率、逾期率必须用汇总后的分子除以汇总后的分母，不能对各渠道比率做AVG。

// 示例：全渠道盈利率仍使用同一个计算字段
SUM(IF [is_mature] = 1 THEN [profit_amt_usd] END)
/
SUM(IF [is_mature] = 1 THEN [due_whole_order_remit_amt_usd] END)

// 不要使用：AVG([各渠道盈利率])

七、每日刷新与发布流程

01 数据库跑数清空暂存表，按T-1全量重算
→
02 自动校验唯一键、窗口数、成熟空值、日期完整性
→
03 事务换表DELETE正式表 + INSERT暂存表；失败回滚
→
04 Tableau刷新数据库成功后再刷新Extract并发送失败告警

调度伪代码

每天 06:00 运行数据库任务
    执行 staging 刷新
    IF 质量检查全部为0:
        在一个事务中替换正式表
        ANALYZE 正式表
    ELSE:
        保留昨日正式表
        发送告警并停止后续任务

每天 07:00 运行 Tableau Extract 刷新
    仅在数据库任务成功后触发
    刷新失败则通知看板负责人
为什么保留暂存表：如果SQL、汇率或源表当天异常，失败发生在暂存表，不会先把正式表清空。正式看板继续显示上一日成功数据，并可通过 refresh_time 发现延迟。

八、数据质量与验收标准

检查项通过标准失败影响
唯一键月份 × 渠道 × 窗口无重复停止换表，防止指标重复汇总。
观察窗口只有30—360共12档停止换表。
成熟空值is_mature=0时生命周期字段均为NULL停止换表。
基础指标本月、上月有首贷人数/金额/成本数据核查源表刷新和渠道映射。
生命周期指标本月、上月为空；更早月份按窗口逐步成熟核查成熟公式。
汇率放款日、还款日无缺失MXN汇率缺失日期不发布，补齐汇率后重跑。
财务恒等式利润 = 还款 − 放款核查流水重复与订单去重。
刷新时间data_date=T-1，refresh_time为当日展示“数据延迟”告警。
上线前抽样：至少选择一个成熟月份、一个未成熟月份、两个渠道和30/90/240/360四个窗口，与原Excel逐项核对分子、分母及最终比率。差异应先定位到底层样本，再检查Tableau公式。

九、实施计划

阶段工作内容交付结果
阶段1｜口径冻结确认渠道映射、利润、逾期、汇率、成熟月份和12个累计窗口。本报告作为统一口径文档。
