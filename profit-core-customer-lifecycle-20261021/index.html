展开完整指标定义

利润与统计订单：2025-01-01至2026-09-30成功放款订单，当前repaid_amt减remit_amt；未结清及状态8保留，回款不截断至9月30日；利润排序和名单冻结于前次统计快照。

生命周期借款次数：截至原利润快照，全历史成功放款订单数；不是当前单的第几次借款。特征取数时点另列。

先分期逾期、后整笔结清：全历史成功放款订单中，任一期overdue_days_period>0，或实际分期还款日期晚于分期应还日期，且整笔is_repaid=1并有有效结清时间。用户占比分母为该客群全部用户；不是当前仍逾期。

用户名下完全结清事件：以整笔实际结清时间为事件时点；按用户全部已放款订单的[放款时间,实际结清时间)重建余额，要求该时点结清后所有在借订单数为0。同一时刻多笔结清合为1次事件；不是结清任一单即计。

5天/7天未再提单：全生命周期完全结清事件，观察已满5×24小时/7×24小时才入相应分母；从结清时刻至其后120/168小时内无任何真实订单提单，记5/7天未再提单。包含失败提单；页面进页不算提单。窗口含终点，结清同刻提单记已提单。

用户率和事件率分母：事件率=未在5/7天内再提单的完全结清事件数/观察成熟事件数；曾发生用户占比=至少发生1次该中断的用户数/至少有1次成熟完全结清事件的用户数。不是所有用户为分母。

结清后再提单间隔：仅已观察到下次提单的完全结清事件计算间隔；先取用户内间隔中位数，再取客群用户中位数，仍未再提单不填0。

提单额度使用率：统计期内提单订单：同用户同serial_id、提单时点前最近获额记录，要求is_pass1=1且max_credit_apply_amt>0；使用率=apply_amt/max_credit_apply_amt。主指标是有效订单使用率算术平均，并列总提单金额/总额度的加权比率。不用放款金额、不把缺失填0、不截断超过100%的值。

当前逾期用户：特征快照下，用户名下任一订单loan_status_code=8；分母为客群全部用户；仅描述不排除。

无当前逾期内的最新获额结果：用户全部获额记录按vir_unix、serial_id、vir_rnb降序取最新一笔；同一时刻取serial_id最大。仅在无当前状态8用户内计算通过/未通过占比，is_pass1=1为通过、0为未通过；未通过不直接等同风控拒绝，缺失单列。

循环贷用户：全历史至少有1笔成功放款订单，side_recycle_type_copy.recycle_type=2。循环贷用户与续贷用户不是同义词；另列最近放款是否循环贷和循环贷订单占比。

借款间隔：按实际成功放款时间排序，相邻成功借款间隔；图表主值先取用户内间隔中位数，再取客群用户中位数。同日借多笔可产生小于1天间隔。

提前结清：整笔实际结清日期严格早于整笔最终应还日期，is_repaid=1；用户占比按全组用户计算。

解释边界：历史中断可在之后再次提单，不等同永久流失；本次不做运营可触达筛选。贷款、分期、获额、循环贷类型分表在相邻只读快照提取，事件统一截止贷款特征快照，未取得不可变历史入库快照，源副本后补会影响复跑结果。

WITH funded AS (
 SELECT user_id,serial_id,remit_time,remit_date,remit_amt,repaid_amt,is_repaid,loan_status_code,loan_type,total_term,overdue_days
 FROM wangchuanliang.order_loan_f_v2_copy
 WHERE is_remit=1 AND remit_time<=CURRENT_TIMESTAMP AT TIME ZONE 'America/Belize'
), lifetime AS (
 SELECT user_id,COUNT(*) AS lifetime_loans,
 MIN(CASE WHEN remit_date>=DATE '2000-01-01' THEN remit_date END) AS first_remit_date,
 MAX(CASE WHEN remit_date>=DATE '2000-01-01' THEN remit_date END) AS last_remit_date,
 MAX(CASE WHEN loan_status_code=8 THEN 1 ELSE 0 END) AS has_current_status8,
 MAX(CASE WHEN loan_status_code=5 THEN 1 ELSE 0 END) AS has_current_status5,
 MAX(overdue_days) AS max_recorded_overdue_days
 FROM funded GROUP BY user_id
), scoped AS (
 SELECT * FROM funded WHERE remit_date>=DATE '2025-01-01' AND remit_date<DATE '2026-10-01'
), user_profit AS (
 SELECT user_id,COUNT(*) AS scoped_orders,SUM(remit_amt) AS remit_amt,SUM(repaid_amt) AS repaid_amt,
 SUM(repaid_amt-remit_amt) AS profit,
 SUM(CASE WHEN is_repaid=1 THEN 1 ELSE 0 END) AS settled_orders,
 SUM(CASE WHEN loan_status_code=8 THEN 1 ELSE 0 END) AS scoped_status8_orders,
 SUM(CASE WHEN loan_type='reloan' THEN 1 ELSE 0 END) AS reloan_orders,
 SUM(total_term) AS total_terms,SUM(CASE WHEN total_term IS NOT NULL THEN 1 ELSE 0 END) AS known_term_orders
 FROM scoped GROUP BY user_id
), features AS (
 SELECT p.*,l.lifetime_loans,l.first_remit_date,l.last_remit_date,
 l.has_current_status8,l.has_current_status5,l.max_recorded_overdue_days,
 ((CURRENT_TIMESTAMP AT TIME ZONE 'America/Belize')::date-l.last_remit_date) AS days_since_last_remit,
 CASE WHEN l.lifetime_loans>1 THEN (l.last_remit_date-l.first_remit_date)::numeric/(l.lifetime_loans-1) ELSE NULL END AS mean_lifetime_borrow_gap_days
 FROM user_profit p JOIN lifetime l ON l.user_id=p.user_id
), totals AS (
 SELECT COUNT(*) AS total_users,SUM(scoped_orders) AS total_orders,
 SUM(remit_amt) AS total_remit_amt,SUM(repaid_amt) AS total_repaid_amt,SUM(profit) AS total_profit,
 SUM(CASE WHEN profit>0 THEN profit ELSE 0 END) AS positive_user_profit,
 SUM(CASE WHEN profit<0 THEN profit ELSE 0 END) AS negative_user_profit,
 SUM(CASE WHEN profit>0 THEN 1 ELSE 0 END) AS profitable_users,
 SUM(lifetime_loans) AS total_lifetime_loans,SUM(settled_orders) AS total_settled_orders,
 SUM(has_current_status8) AS current_status8_users,SUM(has_current_status5) AS current_status5_users,
 SUM(CASE WHEN lifetime_loans>=6 THEN 1 ELSE 0 END) AS loans_ge6_users,
 SUM(CASE WHEN lifetime_loans>=11 THEN 1 ELSE 0 END) AS loans_ge11_users,
 SUM(days_since_last_remit) AS total_days_since_last_remit,
 SUM(total_terms) AS total_terms,SUM(known_term_orders) AS known_term_orders,
 SUM(reloan_orders) AS reloan_orders
 FROM features
), ranked AS (
 SELECT f.*,ROW_NUMBER() OVER(ORDER BY profit DESC,user_id ASC) AS profit_rank,
 SUM(profit) OVER(ORDER BY profit DESC,user_id ASC ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS cumulative_profit
 FROM features f WHERE profit>0
), cutoffs AS (
 SELECT MIN(CASE WHEN r.cumulative_profit>=t.total_profit*0.5 THEN r.profit_rank END) AS k50,
 MIN(CASE WHEN r.cumulative_profit>=t.total_profit*0.6 THEN r.profit_rank END) AS k60,
 MIN(CASE WHEN r.cumulative_profit>=t.total_profit*0.7 THEN r.profit_rank END) AS k70,
 MIN(CASE WHEN r.cumulative_profit>=t.total_profit*0.8 THEN r.profit_rank END) AS k80,
 MIN(CASE WHEN r.cumulative_profit>=t.total_profit*0.9 THEN r.profit_rank END) AS k90
 FROM ranked r CROSS JOIN totals t
)
SELECT r.*,c.k50,c.k60,c.k70,c.k80,c.k90
 FROM ranked r CROSS JOIN cutoffs c WHERE r.profit_rank<=c.k90 ORDER BY r.profit_rank
