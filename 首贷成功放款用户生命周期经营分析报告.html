首贷成功放款用户生命周期经营分析报告

统计对象：首贷提单日在 2024-01-01—2026-06-30 且首贷成功放款的用户。核心目标是识别各客群的无在途（可经营）时间：该时间段尚未形成借款，利润为 0；后续运营应在风险可控前提下，将其缩短并转化为健康在途时间。

一、核心结论

结论 1：报告的经营对象是无在途时间。用户在无在途期间不处于逾期、在途或被拒链路，具备提单资格但尚未形成放款；该阶段不产生借款利润。经营的直接目标不是拉长生命周期，而是在风险可控前提下，把无在途天数转化为健康在途天数。
结论 2：可经营空间集中在已形成复贷行为的用户。成功放款 1 次用户平均无在途仅 0.00 天、占比 0.00%，主要矛盾是首贷后的风险、结清与流失；成功放款 2 次、3 次、4—5 次用户的平均无在途天数依次为 6.37、9.45、15.13 天，开始出现明确的可经营回归空档。
结论 3：高频用户是缩短可经营时间的核心对象。成功放款 6—10 次与 10 次以上用户的平均无在途时间分别为 22.99、35.52 天，占比分别为 11.47%、11.19%。这些用户已验证复贷能力，优先通过结清后分层触达、额度和定价匹配缩短空档，更可能提升生命周期利润。

分层发现

  • 成功放款 1 次：占 45.33%，平均无在途 0.00 天。该组空档较短，不宜仅靠召回解释，应优先处理首贷风险、结清和早期流失。
  • 成功放款 2—3 次：无在途时间分别为 6.37 与 9.45 天，说明用户完成结清后已出现可压缩的回归空档。
  • 成功放款 4—5 次：平均无在途 15.13 天，是兼具规模和可经营空间的重点观察层。
  • 成功放款 6 次以上：平均无在途为 22.99—35.52 天，绝对空档最长；即使占比趋稳，缩短每次结清后的等待仍可累计增加在途与利润机会。

运营优先级

  • 1 次：先降低早期逾期和首贷后流失，再讨论扩大复贷转化。
  • 2—3 次：围绕结清后短窗口做回归引导，并识别被拒链路中可修复的原因。
  • 4—5 次：按结清后天数、额度、息费敏感度与历史履约分层触达，直接目标是缩短无在途时间。
  • 6 次以上：建立长期价值经营节奏，评估“减少 1 天无在途”带来的新增放款、逾期与净利润，而非只追求放款次数。

五、统计口径与解释边界

  • 五类状态：按 逾期 > 被拒 > 在途 > 流失 > 正常结清 顺序判定；生命周期终点随状态而变化。
  • 日状态：按 逾期 > 在途 > 被拒 > 无在途 覆盖。逾期结清当日又提单，仍计逾期；被拒后同日成功放款，计在途。
  • 可经营时间：只有“结清后的下一次提单直接成功放款”时，结清次日至该成功放款提单日前一天才计为无在途；若下一次提单被拒，则从结清次日起至下一次成功放款提单日前一天均属于被拒链路，不计无在途。
  • 解读边界：本报告为当前状态和历史时间结构的描述性统计，不直接证明触达或让利一定带来净利润提升。策略上线需同时评估放款、逾期、让利和利润增量。

附录：可复现全部指标的 PGSQL

以下代码使用订单表 wangchuanliang.order_loan_f_v2_copy，输出报告所用的五类状态汇总、成功放款次数汇总及二者交叉汇总。

模块 1：样本、状态与生命周期终点
-- ================================================================
-- 首贷成功放款用户生命周期：当前状态 × 成功放款次数分层
-- 统计截止日：CURRENT_DATE
-- 统计对象：2024-01-01 至 2026-06-30 首贷提单且成功放款的用户
-- 日状态优先级：逾期 > 在途 > 被拒 > 无在途
-- ================================================================

WITH params AS (
    SELECT CURRENT_DATE::date AS as_of_date
),

-- 1. 首贷成功放款 cohort：每个用户仅保留首贷成功放款订单。
first_loan_cohort AS (
    SELECT
        o.user_id,
        o.apply_date AS first_loan_apply_date
    FROM wangchuanliang.order_loan_f_v2_copy AS o
    WHERE o.is_remit = 1
      AND o.loan_type = 'firstloan'
      AND o.apply_date BETWEEN DATE '2024-01-01' AND DATE '2026-06-30'
),

-- 2. 取得 cohort 用户的全量订单；apply_time、serial_id 共同保证“最后一笔提单”唯一。
user_orders AS (
    SELECT
        c.user_id,
        c.first_loan_apply_date,
        o.serial_id,
        o.apply_date,
        o.apply_time,
        o.due_date,
        o.repaid_time,
        o.repaid_date,
        o.is_remit,
        o.overdue_days,
        o.loan_status_code,
        ROW_NUMBER() OVER (
            PARTITION BY c.user_id
            ORDER BY o.apply_time DESC, o.serial_id DESC
        ) AS apply_desc_rn,
        MIN(CASE WHEN o.is_remit = 1 THEN o.apply_date END) OVER (
            PARTITION BY c.user_id
            ORDER BY o.apply_time, o.serial_id
            ROWS BETWEEN 1 FOLLOWING AND UNBOUNDED FOLLOWING
        ) AS next_success_apply_date
    FROM first_loan_cohort AS c
    INNER JOIN wangchuanliang.order_loan_f_v2_copy AS o
        ON o.user_id = c.user_id
),

-- 3. 当前用户状态的必要信息。
user_state_base AS (
    SELECT
        u.user_id,
        MAX(u.first_loan_apply_date) AS first_loan_apply_date,
        MIN(CASE WHEN u.loan_status_code = 8 THEN u.due_date END) AS earliest_current_overdue_due_date,
        MAX(CASE WHEN u.loan_status_code = 5 THEN u.due_date END) AS latest_current_in_transit_due_date,
        MAX(CASE
            WHEN u.is_remit = 1
             AND u.repaid_date > DATE '2000-01-01'
            THEN u.repaid_date
        END) AS last_valid_repaid_date,
        MAX(CASE WHEN u.apply_desc_rn = 1 THEN u.is_remit END) AS last_apply_is_remit,
        MAX(CASE WHEN u.apply_desc_rn = 1 THEN u.apply_date END) AS last_apply_date
    FROM user_orders AS u
    GROUP BY u.user_id
),

-- 4. 五类当前状态与生命周期终点。
lifecycle_base AS (
    SELECT
        s.user_id,
        s.first_loan_apply_date AS lifecycle_start,
        CASE
            WHEN s.earliest_current_overdue_due_date IS NOT NULL THEN '逾期状态'
            WHEN s.last_apply_is_remit = 0 THEN '被拒状态'
            WHEN s.latest_current_in_transit_due_date IS NOT NULL THEN '在途状态'
            WHEN s.last_valid_repaid_date < p.as_of_date - 7 THEN '流失状态'
            ELSE '正常结清状态'
        END AS user_status,
        CASE
            WHEN s.earliest_current_overdue_due_date IS NOT NULL THEN s.earliest_current_overdue_due_date
            WHEN s.last_apply_is_remit = 0 THEN s.last_apply_date
            WHEN s.latest_current_in_transit_due_date IS NOT NULL THEN s.latest_current_in_transit_due_date
            ELSE s.last_valid_repaid_date
        END AS lifecycle_end
    FROM user_state_base AS s
    CROSS JOIN params AS p
),

-- 防御性过滤：只保留生命周期终点不早于首贷提单日的用户。
lifecycle_users AS (
    SELECT
        l.*,
        (l.lifecycle_end - l.lifecycle_start + 1)::bigint AS lifecycle_days
    FROM lifecycle_base AS l
    WHERE l.lifecycle_end >= l.lifecycle_start
),
模块 2：成功放款次数与四类区间
-- 5. 成功放款次数：统计生命周期终点及以前的成功放款整笔订单。
user_loan_count AS (
    SELECT
        l.user_id,
        COUNT(DISTINCT CASE
            WHEN o.is_remit = 1
             AND o.apply_date <= l.lifecycle_end
            THEN o.serial_id
        END) AS success_loan_cnt
    FROM lifecycle_users AS l
    INNER JOIN user_orders AS o
        ON o.user_id = l.user_id
    GROUP BY l.user_id
),

lifecycle_population AS (
    SELECT
        l.*,
        CASE
            WHEN c.success_loan_cnt = 1 THEN '成功放款1次'
            WHEN c.success_loan_cnt = 2 THEN '成功放款2次'
            WHEN c.success_loan_cnt = 3 THEN '成功放款3次'
            WHEN c.success_loan_cnt BETWEEN 4 AND 5 THEN '成功放款4-5次'
            WHEN c.success_loan_cnt BETWEEN 6 AND 10 THEN '成功放款6-10次'
            WHEN c.success_loan_cnt > 10 THEN '成功放款10次以上'
        END AS success_loan_group
    FROM lifecycle_users AS l
    INNER JOIN user_loan_count AS c
        ON c.user_id = l.user_id
),

-- 6. 三类可被日状态覆盖的区间。每个区间均裁剪到生命周期内。
-- 6.1 历史逾期且已结清：到期日次日开始，结清日仍计逾期。
overdue_intervals AS (
    SELECT
        p.user_id,
        GREATEST(o.due_date + 1, p.lifecycle_start) AS start_date,
        CASE
            WHEN o.repaid_date > DATE '2000-01-01'
            THEN LEAST(o.repaid_date, p.lifecycle_end)
            ELSE p.lifecycle_end
        END AS end_date,
        1 AS overdue_delta,
        0 AS in_transit_delta,
        0 AS rejected_delta,
        0 AS idle_delta
    FROM lifecycle_population AS p
    INNER JOIN user_orders AS o
        ON o.user_id = p.user_id
    WHERE o.is_remit = 1
      AND o.loan_status_code <> 8
      AND (
          (o.overdue_days > 0
           AND o.repaid_date > DATE '2000-01-01'
           AND o.repaid_date > o.due_date)
          -- 数据质量兜底：状态非8但结清日期仍为时间戳0，视为未结清逾期。
          OR (o.repaid_date <= DATE '2000-01-01'
              AND o.due_date < p.lifecycle_end)
      )
),

-- 6.2 成功放款在途：提单日和到期日均计入；提前结清则结清日为最后在途日。
in_transit_intervals AS (
    SELECT
        p.user_id,
        GREATEST(o.apply_date, p.lifecycle_start) AS start_date,
        LEAST(
            CASE
                -- 当前状态为 8 时，即使明细里出现异常的历史结清日，
                -- 仍按未结清订单处理：在途持续到到期日，再由逾期状态覆盖到期日。
                WHEN o.loan_status_code <> 8
                 AND o.repaid_date > DATE '2000-01-01'
                 AND o.repaid_date < o.due_date
                THEN o.repaid_date
                ELSE o.due_date
            END,
            p.lifecycle_end
        ) AS end_date,
        0 AS overdue_delta,
        1 AS in_transit_delta,
        0 AS rejected_delta,
        0 AS idle_delta
    FROM lifecycle_population AS p
    INNER JOIN user_orders AS o
        ON o.user_id = p.user_id
    WHERE o.is_remit = 1
),

-- 6.3 被拒链路：从上一笔成功订单结清次日开始，直至下一次成功放款提单日前一天。
-- 因此，结清后最终发生被拒提单前的空档也属于被拒，而非无在途。
previous_settlement_before_rejection AS (
    SELECT
        r.user_id,
        r.serial_id,
        MAX(s.repaid_date) AS previous_repaid_date
    FROM user_orders AS r
    INNER JOIN user_orders AS s
        ON s.user_id = r.user_id
       AND s.is_remit = 1
       AND s.repaid_date > DATE '2000-01-01'
       AND s.repaid_time < r.apply_time
    WHERE r.is_remit = 0
    GROUP BY r.user_id, r.serial_id
),

rejected_intervals AS (
    SELECT
        p.user_id,
        GREATEST(previous.previous_repaid_date + 1, p.lifecycle_start) AS start_date,
        LEAST(
            COALESCE(o.next_success_apply_date - 1, p.lifecycle_end),
            p.lifecycle_end
        ) AS end_date,
        0 AS overdue_delta,
        0 AS in_transit_delta,
        1 AS rejected_delta,
        0 AS idle_delta
    FROM lifecycle_population AS p
    INNER JOIN user_orders AS o
        ON o.user_id = p.user_id
    INNER JOIN previous_settlement_before_rejection AS previous
        ON previous.user_id = o.user_id
       AND previous.serial_id = o.serial_id
    WHERE o.is_remit = 0
),

-- 6.4 每笔已结清订单对应的“下一笔提单”及其结果；不用 LATERAL，兼容当前数据库方言。
next_apply_candidates AS (
    SELECT
        o.user_id,
        o.serial_id AS settled_serial_id,
        o2.apply_date AS next_apply_date,
        o2.is_remit AS next_apply_is_remit,
        ROW_NUMBER() OVER (
            PARTITION BY o.user_id, o.serial_id
            ORDER BY o2.apply_time, o2.serial_id
        ) AS next_apply_rn
    FROM user_orders AS o
    INNER JOIN user_orders AS o2
        ON o2.user_id = o.user_id
       AND o2.apply_date > o.repaid_date
    WHERE o.is_remit = 1
      AND o.repaid_date > DATE '2000-01-01'
),

next_apply_after_repayment AS (
    SELECT
        user_id,
        settled_serial_id,
        next_apply_date,
        next_apply_is_remit
    FROM next_apply_candidates
    WHERE next_apply_rn = 1
),

-- 6.5 无在途：只有下一次提单直接成功放款时，才统计结清次日至该提单日前一天。
-- 若下一次提单被拒，则整段属于被拒链路，绝不归为无在途。
idle_intervals AS (
    SELECT
        p.user_id,
        GREATEST(o.repaid_date + 1, p.lifecycle_start) AS start_date,
        LEAST(
            COALESCE(next_apply.next_apply_date - 1, p.lifecycle_end),
            p.lifecycle_end
        ) AS end_date,
        0 AS overdue_delta,
        0 AS in_transit_delta,
        0 AS rejected_delta,
        1 AS idle_delta
    FROM lifecycle_population AS p
    INNER JOIN user_orders AS o
        ON o.user_id = p.user_id
    LEFT JOIN next_apply_after_repayment AS next_apply
        ON next_apply.user_id = o.user_id
       AND next_apply.settled_serial_id = o.serial_id
    WHERE o.is_remit = 1
      AND o.repaid_date > DATE '2000-01-01'
      AND next_apply.next_apply_is_remit = 1
),

valid_intervals AS (
    SELECT * FROM overdue_intervals WHERE start_date <= end_date
    UNION ALL
    SELECT * FROM in_transit_intervals WHERE start_date <= end_date
    UNION ALL
    SELECT * FROM rejected_intervals WHERE start_date <= end_date
    UNION ALL
    SELECT * FROM idle_intervals WHERE start_date <= end_date
),
模块 3：事件流拆分、汇总与输出
-- 7. 事件流法：避免生成用户 × 每天的明细，也能合并重叠区间。
-- 每个状态区间 [start_date, end_date] 转成 start +1、end_date+1 -1 两个事件。
raw_events AS (
    SELECT
        p.user_id,
        p.lifecycle_start AS event_date,
        0::bigint AS overdue_delta,
        0::bigint AS in_transit_delta,
        0::bigint AS rejected_delta,
        0::bigint AS idle_delta
    FROM lifecycle_population AS p
    UNION ALL
    SELECT
        p.user_id,
        p.lifecycle_end + 1 AS event_date,
        0::bigint,
        0::bigint,
        0::bigint,
        0::bigint
    FROM lifecycle_population AS p
    UNION ALL
    SELECT
        i.user_id,
        i.start_date,
        i.overdue_delta::bigint,
        i.in_transit_delta::bigint,
        i.rejected_delta::bigint,
        i.idle_delta::bigint
    FROM valid_intervals AS i
    UNION ALL
    SELECT
        i.user_id,
        i.end_date + 1,
        -i.overdue_delta::bigint,
        -i.in_transit_delta::bigint,
        -i.rejected_delta::bigint,
        -i.idle_delta::bigint
    FROM valid_intervals AS i
),

event_deltas AS (
    SELECT
        user_id,
        event_date,
        SUM(overdue_delta) AS overdue_delta,
        SUM(in_transit_delta) AS in_transit_delta,
        SUM(rejected_delta) AS rejected_delta,
        SUM(idle_delta) AS idle_delta
    FROM raw_events
    GROUP BY user_id, event_date
),

running_events AS (
    SELECT
        e.user_id,
        e.event_date,
        LEAD(e.event_date) OVER (
            PARTITION BY e.user_id ORDER BY e.event_date
        ) AS next_event_date,
        SUM(e.overdue_delta) OVER (
            PARTITION BY e.user_id ORDER BY e.event_date
            ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
        ) AS active_overdue_cnt,
        SUM(e.in_transit_delta) OVER (
            PARTITION BY e.user_id ORDER BY e.event_date
            ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
        ) AS active_in_transit_cnt,
        SUM(e.rejected_delta) OVER (
            PARTITION BY e.user_id ORDER BY e.event_date
            ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
        ) AS active_rejected_cnt,
        SUM(e.idle_delta) OVER (
            PARTITION BY e.user_id ORDER BY e.event_date
            ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
        ) AS active_idle_cnt
    FROM event_deltas AS e
),

user_day_segments AS (
    SELECT
        r.user_id,
        (r.next_event_date - r.event_date)::bigint AS segment_days,
        CASE
            WHEN r.active_overdue_cnt > 0 THEN '逾期天数'
            WHEN r.active_in_transit_cnt > 0 THEN '在途天数'
            WHEN r.active_rejected_cnt > 0 THEN '被拒天数'
            WHEN r.active_idle_cnt > 0 THEN '无在途天数'
            ELSE '未归类天数'
        END AS day_status
    FROM running_events AS r
    WHERE r.next_event_date > r.event_date
),

user_metrics AS (
    SELECT
        p.user_id,
        p.user_status,
        p.success_loan_group,
        p.lifecycle_days,
        COALESCE(SUM(CASE WHEN s.day_status = '逾期天数' THEN s.segment_days END), 0) AS overdue_days,
        COALESCE(SUM(CASE WHEN s.day_status = '在途天数' THEN s.segment_days END), 0) AS in_transit_days,
        COALESCE(SUM(CASE WHEN s.day_status = '被拒天数' THEN s.segment_days END), 0) AS rejected_days,
        COALESCE(SUM(CASE WHEN s.day_status = '无在途天数' THEN s.segment_days END), 0) AS idle_days
    FROM lifecycle_population AS p
    LEFT JOIN user_day_segments AS s
        ON s.user_id = p.user_id
    GROUP BY p.user_id, p.user_status, p.success_loan_group, p.lifecycle_days
),

-- 8. 输出：五类用户总计，以及五类用户 × 成功放款次数。
summary_rows AS (
    SELECT
        '五类用户总计' AS report_layer,
        user_status,
        '全部成功放款次数' AS success_loan_group,
        COUNT(*) AS user_cnt,
        AVG(lifecycle_days)::numeric(18,2) AS avg_lifecycle_days,
        AVG(overdue_days)::numeric(18,2) AS avg_overdue_days,
        AVG(in_transit_days)::numeric(18,2) AS avg_in_transit_days,
        AVG(rejected_days)::numeric(18,2) AS avg_rejected_days,
        AVG(idle_days)::numeric(18,2) AS avg_idle_days,
        AVG(overdue_days::numeric / NULLIF(lifecycle_days, 0)) AS avg_overdue_ratio,
        AVG(in_transit_days::numeric / NULLIF(lifecycle_days, 0)) AS avg_in_transit_ratio,
        AVG(rejected_days::numeric / NULLIF(lifecycle_days, 0)) AS avg_rejected_ratio,
        AVG(idle_days::numeric / NULLIF(lifecycle_days, 0)) AS avg_idle_ratio
    FROM user_metrics
    GROUP BY user_status

    UNION ALL

    SELECT
        '成功放款次数总计' AS report_layer,
        '全部当前状态' AS user_status,
        success_loan_group,
        COUNT(*) AS user_cnt,
        AVG(lifecycle_days)::numeric(18,2) AS avg_lifecycle_days,
        AVG(overdue_days)::numeric(18,2) AS avg_overdue_days,
        AVG(in_transit_days)::numeric(18,2) AS avg_in_transit_days,
        AVG(rejected_days)::numeric(18,2) AS avg_rejected_days,
        AVG(idle_days)::numeric(18,2) AS avg_idle_days,
        AVG(overdue_days::numeric / NULLIF(lifecycle_days, 0)) AS avg_overdue_ratio,
        AVG(in_transit_days::numeric / NULLIF(lifecycle_days, 0)) AS avg_in_transit_ratio,
        AVG(rejected_days::numeric / NULLIF(lifecycle_days, 0)) AS avg_rejected_ratio,
        AVG(idle_days::numeric / NULLIF(lifecycle_days, 0)) AS avg_idle_ratio
    FROM user_metrics
    GROUP BY success_loan_group

    UNION ALL

    SELECT
        '五类用户×成功放款次数' AS report_layer,
        user_status,
        success_loan_group,
        COUNT(*) AS user_cnt,
        AVG(lifecycle_days)::numeric(18,2),
        AVG(overdue_days)::numeric(18,2),
        AVG(in_transit_days)::numeric(18,2),
        AVG(rejected_days)::numeric(18,2),
        AVG(idle_days)::numeric(18,2),
        AVG(overdue_days::numeric / NULLIF(lifecycle_days, 0)),
        AVG(in_transit_days::numeric / NULLIF(lifecycle_days, 0)),
        AVG(rejected_days::numeric / NULLIF(lifecycle_days, 0)),
        AVG(idle_days::numeric / NULLIF(lifecycle_days, 0))
    FROM user_metrics
    GROUP BY user_status, success_loan_group
)

SELECT
    report_layer,
    user_status,
    success_loan_group,
    user_cnt,
    avg_lifecycle_days,
    avg_overdue_days,
    avg_in_transit_days,
    avg_rejected_days,
    avg_idle_days,
    ROUND(avg_overdue_ratio * 100, 2) AS avg_overdue_ratio_pct,
    ROUND(avg_in_transit_ratio * 100, 2) AS avg_in_transit_ratio_pct,
    ROUND(avg_rejected_ratio * 100, 2) AS avg_rejected_ratio_pct,
    ROUND(avg_idle_ratio * 100, 2) AS avg_idle_ratio_pct
FROM summary_rows
ORDER BY
    CASE report_layer
        WHEN '五类用户总计' THEN 1
        WHEN '成功放款次数总计' THEN 2
        ELSE 3
    END,
    CASE user_status
        WHEN '逾期状态' THEN 1
        WHEN '被拒状态' THEN 2
        WHEN '在途状态' THEN 3
        WHEN '流失状态' THEN 4
        WHEN '正常结清状态' THEN 5
    END,
    CASE success_loan_group
        WHEN '全部成功放款次数' THEN 0
        WHEN '成功放款1次' THEN 1
        WHEN '成功放款2次' THEN 2
        WHEN '成功放款3次' THEN 3
        WHEN '成功放款4-5次' THEN 4
        WHEN '成功放款6-10次' THEN 5
        WHEN '成功放款10次以上' THEN 6
    END;
