COUPON DATA · CLASSIFICATION & MEASUREMENT

红包分类、使用方法与统计口径说明

适用表：coupon_user_detail_copy、order_loan_f_v2_copy、repayment_plan_v2_copy

一、核心结论：统计前必须统一数据粒度

红包表的一行不是天然的一张券，也不是天然的一笔订单。多期订单会产生多条红包明细，因此需先聚合、后关联。

红包明细
user_id + serial_id + coupon_no + current_term
一张券可拆成多期记录
→
订单级红包
user_id + serial_id
用于提单、放款、盈利、逾期
→
分期级红包
serial_id + current_term
用于每期还款、逾期、优惠
统一原则：订单级分析先汇总至 user_id + serial_id；分期级分析先汇总至 serial_id + current_term。直接将订单或分期表关联红包明细，会导致订单数、分期数和金额被重复计算。

二、红包分类及每类红包的统计方式

type = 3｜降息券

对利息或息费按比例减免，主要是 10%，也包括 5%、20%、30% 等。

规则：一笔订单理论上只有一个 coupon_no；多期订单有多条明细，但券号相同。

订单红包金额：SUM(coupon_amount)，即所有期数金额之和。

type = 4｜提额券

用于提升可获额度，例如 5%、10%、20% 提额。

规则：一笔订单理论上只有一个 coupon_no；多期订单按期产生多条明细。

订单红包金额：SUM(coupon_amount)。

type = 2｜提前还款折扣券

用户提前还款时享受的优惠或折扣。

规则：一笔订单可以有多张券，coupon_no 不唯一。

订单券数：COUNT(DISTINCT coupon_no)；总金额：SUM(coupon_amount)。

三、字段口径与关联键

字段含义统计用途
user_id用户标识订单级关联建议与 serial_id 同时使用，保障订单归属一致。
serial_id订单标识订单表与红包表的核心关联键。
current_term当前期数分期表与红包表关联键；订单级统计时不分期，而是汇总所有期。
coupon_no红包编号一张独立券的标识。type=2 必须使用它去重计算券数。
coupon_amount红包金额按订单或分期粒度汇总后的优惠金额。
create_time红包创建时间用于分析发券至提单、还款的时间间隔；订单级通常取 MIN(create_time)。

四、订单级统计：识别哪些提单／放款订单使用红包

订单级的目标是一笔订单只保留一行，适用于提单、放款、盈利、风险等指标。

提单订单 = order_loan_f_v2_copy 中 apply_date IS NOT NULL 的订单
放款订单 = 提单订单中 is_remit = 1 的订单

1. 订单级聚合伪代码

输入：coupon_user_detail_copy（红包明细）
输出：每笔订单一行的 coupon_order_wide

降息券订单汇总(type=3) =
    红包明细 where type=3
    group by user_id, serial_id
    calculate:
        coupon_no       = MAX(coupon_no)          -- 每单理论上一张
        coupon_amt      = SUM(coupon_amount)      -- 多期金额相加
        create_time     = MIN(create_time)

提额券订单汇总(type=4) =
    红包明细 where type=4
    group by user_id, serial_id
    calculate:
        coupon_no       = MAX(coupon_no)
        coupon_amt      = SUM(coupon_amount)
        create_time     = MIN(create_time)

还款优惠券订单汇总(type=2) =
    红包明细 where type=2
    group by user_id, serial_id
    calculate:
        coupon_cnt      = COUNT(DISTINCT coupon_no)
        coupon_amt      = SUM(coupon_amount)
        create_time     = MIN(create_time)

提单订单红包宽表 =
    提单订单
    LEFT JOIN 还款优惠券订单汇总 ON user_id + serial_id
    LEFT JOIN 降息券订单汇总     ON user_id + serial_id
    LEFT JOIN 提额券订单汇总     ON user_id + serial_id
    derive:
        has_repay_coupon    = IF(匹配到type=2, 1, 0)
        has_interest_coupon = IF(匹配到type=3, 1, 0)
        has_quota_coupon    = IF(匹配到type=4, 1, 0)

2. 建议保留的订单级字段

字段定义可用于的分析
has_interest_coupon匹配 type=3 则为 1降息券关联订单、提单率、放款率、盈利率
interest_coupon_amttype=3 的全期 SUM(coupon_amount)降息总成本、券力度分层
has_quota_coupon匹配 type=4 则为 1提额券订单与额度使用率、提单金额关系
quota_coupon_amttype=4 的全期 SUM(coupon_amount)提额价值或成本分析
has_repay_coupon匹配 type=2 则为 1还款优惠券覆盖和还款表现
repay_coupon_cnt / amttype=2 的券数 / 总金额多券使用、优惠成本与提前还款关系

五、分期级统计：识别每一期红包使用

分析每期逾期、每期还款、提前还款优惠时，必须使用期级关联，订单级聚合结果不能直接替代。

分期级关联键 = repayment_plan_v2_copy.serial_id + repayment_plan_v2_copy.current_term
分期级还款优惠券(type=2) =
    红包明细 where type=2
    group by serial_id, current_term
    calculate:
        coupon_cnt   = COUNT(DISTINCT coupon_no)
        coupon_amt   = SUM(coupon_amount)
        create_time  = MIN(create_time)

分期红包宽表 =
    repayment_plan_v2_copy
    LEFT JOIN 分期级还款优惠券
        ON serial_id + current_term

-- type=3、type=4 也按 serial_id + current_term 关联，
-- 可得到每期降息金额、每期提额券金额。
金额边界：“某一期红包金额”是该期的 SUM(coupon_amount)；“一笔订单红包金额”是订单所有期红包金额之和。两类金额不能直接相加或相互替代。

六、核心统计指标及公式

红包覆盖与金额

降息券提单订单占比 = 使用降息券的提单订单数 ÷ 全部提单订单数
降息券放款率 = 使用降息券且放款订单数 ÷ 使用降息券提单订单数
单笔降息券金额 = SUM(interest_coupon_amt) ÷ 使用降息券订单数

转化、风险与盈利

券组提单率 = 使用该券的提单用户数 ÷ 对应可触达或获券用户数
券组逾期率 = 使用该券且状态为8的放款订单数 ÷ 使用该券放款订单数
券组盈利率 = 状态为7、8的SUM(repaid_amt) ÷ SUM(remit_amt) − 1
“使用”的解释边界：当前口径将“红包表存在与订单关联的记录”视为该订单使用/关联该红包。如果后续需要严格区分“已发放、已绑定、已核销、已作废”，则需要红包表中的核销状态、使用时间或作废状态字段，并将其加入筛选条件。

七、常见错误与数据核对规则

风险点错误做法正确做法
多期重复订单表直接关联红包明细后统计订单数先按 user_id + serial_id 聚合，再关联订单表
type=2 多券用 COUNT(*) 代表红包张数使用 COUNT(DISTINCT coupon_no)
期级重复分期表直接关联 type=2 明细先按 serial_id + current_term 聚合
金额混用把单期红包金额当作订单总红包金额订单级汇总所有期；分期级只统计本期
唯一性核对忽略 type=3 / type=4 是否出现多券核对 COUNT(DISTINCT coupon_no)；正常应不大于1

八、建议的后续分析路径

  1. 降息券：按 5%、10%、20%、30% 力度分层，比较提单率、放款率、逾期率、盈利率和单位增量成本。
  2. 提额券：比较提额券用户的提单金额、额度使用率、放款率与后续风险表现。
  3. 还款优惠券：在分期级比较提前还款、逾期结清、复借及优惠成本。
  4. 组合券：形成“仅降息、仅提额、仅还款、组合券、无券”等互斥分组，统一比较全链路转化和风险质量。
标准执行顺序：确定订单级或分期级 → 先按目标粒度聚合红包 → 再关联订单/分期表 → 最后统计提单、放款、逾期、盈利与红包成本。
