三、核心结论与业务解读

01 / 活跃贡献随等待阈值上升

第一阶段活跃用户贡献了更多第二阶段提单

T3、T5、T7 中，第一阶段活跃用户分别贡献 50.60%（11,272 人）、56.01%（9,940 人）、58.88%（8,523 人）的第二阶段首次提单；T7 比 T3 高 8.28 个百分点。等待窗口越长，先进入 App 的用户在后续提单人群中的贡献越大。

02 / 明显的“早提单”特征

第一阶段活跃用户在阶段二前段更集中

第 1–3 天时，第一阶段活跃用户占该时段提单人群的比例为 T3 62.48%、T5 69.27%、T7 72.30%；到第 31 天及以后则降至 33.88%、39.10%、42.28%。三组均下降约 28–30 个百分点，支持“第一阶段活跃与更早的后续提单相关”的判断。

03 / 新增活跃是长尾提单的主要来源

超过 30 天的提单以阶段二新增活跃为主

第 31 天及以后，新增活跃用户占比为 T3 66.12%、T5 60.90%、T7 57.72%。这部分不是第一阶段触达已唤起的人群，较适合用阶段二的召回、消息触达或产品入口优化承接。

04 / 第二阶段提单并未只发生在起始几天

前 7 天与长尾窗口需要并行经营

阶段二第 1–7 天的提单占比为 T3 49.87%、T5 45.24%、T7 40.47%；第 16 天及以后仍分别有 30.38%、34.69%、38.65%。尤其 T7 长尾更重，不能只把运营资源放在阶段二开始后的短窗口。

05 / 口径边界

本报告衡量“首次后续提单”的时间，不衡量频次

每次符合条件的结清事件仅连接紧随其后的首笔申请，因此同一用户在第二阶段内的多次申请没有累计。这足以判断首次提单时点与第一阶段活跃的关联；若要验证“活跃用户是否提单更多次”，须另行统计窗口内全部 apply_time。

06 / 可行动方向

按阶段分层，而非用同一策略覆盖全部人群

阶段二第 1–7 天优先服务第一阶段已活跃人群，强化额度、期限等转化动作；第 16 天后则将新增活跃用户作为主目标，评估入口曝光和唤回链路。T7 的长尾占比最高（38.65%），更值得设计延迟触达节奏。

附录：完整 PGSQL 查询代码（含口径注释）
/*
  T3/T5/T7 第二阶段首次提单时效分布与第一阶段活跃构成。
  活跃仅以 event_track.active_date 在第一阶段存在记录判断；不使用 active_status。
  第二阶段相对天数：从第二阶段起点计，第 1 天=结清日 + threshold_days + 1。
*/
WITH
all_orders AS (
    SELECT user_id, serial_id, apply_time, remit_time, repaid_time, repaid_date,
           remit_date, loan_status_code, is_remit, reg_date
    FROM wangchuanliang.order_loan_f_v2_copy
    WHERE reg_date BETWEEN DATE '2026-01-01' AND DATE '2026-07-15'
      AND apply_time IS NOT NULL
),
all_users AS (
    SELECT DISTINCT user_id FROM all_orders
    WHERE is_remit = 1 AND remit_date > DATE '2026-01-01'
),
settled_raw AS (
    SELECT o.user_id, o.serial_id, o.repaid_date, o.repaid_time,
           ROW_NUMBER() OVER (PARTITION BY o.user_id ORDER BY o.repaid_time, o.serial_id) AS settle_seq
    FROM all_orders o JOIN all_users u ON u.user_id = o.user_id
    WHERE o.is_remit = 1 AND o.loan_status_code = 7
      AND o.repaid_time IS NOT NULL AND o.remit_time IS NOT NULL
),
clean_settle AS (
    SELECT s.* FROM settled_raw s
    WHERE NOT EXISTS (
        SELECT 1 FROM all_orders o2
        WHERE o2.user_id = s.user_id AND o2.serial_id <> s.serial_id
          AND o2.apply_time < s.repaid_time
          AND (o2.loan_status_code IN (5, 8)
               OR (o2.loan_status_code = 7 AND o2.repaid_time > s.repaid_time))
    )
),
credit_pass AS (
    SELECT DISTINCT ON (v.user_id, v.vir_date)
           v.user_id, v.vir_date, to_timestamp(v.vir_unix) AS vir_time
    FROM wangchuanliang.order_vir_f_copy v
    WHERE v.is_pass1 = 1 AND v.vir_date > DATE '2026-01-01'
    ORDER BY v.user_id, v.vir_date, to_timestamp(v.vir_unix) DESC
),
eligible AS (
    SELECT cs.* FROM clean_settle cs
    JOIN credit_pass cp ON cp.user_id = cs.user_id
                       AND cp.vir_date = cs.repaid_date::date
                       AND cp.vir_time > cs.repaid_time
),
applies AS (
    SELECT user_id, apply_time FROM all_orders
    WHERE apply_time > TIMESTAMP '2026-01-01'
),
merged AS (
    SELECT user_id, repaid_time AS ts, 'settle' AS kind, settle_seq::float AS settle_seq FROM eligible
    UNION ALL
    SELECT user_id, apply_time, 'apply', NULL::float FROM applies
),
ranked AS (
    SELECT *, ROW_NUMBER() OVER (
        PARTITION BY user_id
        ORDER BY ts, CASE kind WHEN 'settle' THEN 0 ELSE 1 END
    ) AS rn
    FROM merged
),
pairs AS (
    SELECT s.user_id, s.ts AS repaid_time, s.settle_seq, a.ts AS next_apply_time
    FROM ranked s
    LEFT JOIN ranked a ON a.user_id = s.user_id AND a.rn = s.rn + 1 AND a.kind = 'apply'
    WHERE s.kind = 'settle'
),
thresholds AS (
    SELECT 'T3' AS cohort, 3 AS threshold_days
    UNION ALL SELECT 'T5', 5
    UNION ALL SELECT 'T7', 7
),
/* 仅保留第二阶段真实提单的首次后续提单事件。 */
phase2_apply AS (
    SELECT
        t.cohort,
        t.threshold_days,
        p.user_id,
        p.repaid_time::date AS repaid_date,
        p.next_apply_time::date AS apply_date,
        p.next_apply_time::date - (p.repaid_time::date + t.threshold_days) AS phase2_day,
        p.repaid_time::date + 1 AS phase1_start_date,
        p.repaid_time::date + t.threshold_days AS phase1_end_date
    FROM pairs p
    CROSS JOIN thresholds t
    WHERE p.settle_seq <= 10
      AND p.next_apply_time IS NOT NULL
      AND p.next_apply_time::date > p.repaid_time::date + t.threshold_days
),
/* 直接关联窗口内的 event_track；避免对每笔事件执行相关子查询。 */
phase2_labeled AS (
    SELECT
        p.*,
        CASE WHEN COUNT(e.active_date) > 0
             THEN '第一阶段活跃'
             ELSE '第二阶段新增活跃'
        END AS activity_group
    FROM phase2_apply p
    LEFT JOIN wangchuanliang.event_track e
      ON e.user_id = p.user_id
     AND e.active_date >= p.phase1_start_date
     AND e.active_date <= p.phase1_end_date
    GROUP BY
        p.cohort, p.threshold_days, p.user_id, p.repaid_date,
        p.apply_date, p.phase2_day, p.phase1_start_date, p.phase1_end_date
),
bucketed AS (
    SELECT *,
        CASE
            WHEN phase2_day BETWEEN 1 AND 3 THEN '第1-3天'
            WHEN phase2_day BETWEEN 4 AND 5 THEN '第4-5天'
            WHEN phase2_day BETWEEN 6 AND 7 THEN '第6-7天'
            WHEN phase2_day BETWEEN 8 AND 15 THEN '第8-15天'
            WHEN phase2_day BETWEEN 16 AND 30 THEN '第16-30天'
            ELSE '第31天及以后'
        END AS timing_bucket,
        CASE
            WHEN phase2_day BETWEEN 1 AND 3 THEN 1
            WHEN phase2_day BETWEEN 4 AND 5 THEN 2
            WHEN phase2_day BETWEEN 6 AND 7 THEN 3
            WHEN phase2_day BETWEEN 8 AND 15 THEN 4
            WHEN phase2_day BETWEEN 16 AND 30 THEN 5
            ELSE 6
        END AS bucket_order
    FROM phase2_labeled
)
SELECT
    cohort,
    timing_bucket,
    COUNT(*) AS phase2_apply_events,
    ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (PARTITION BY cohort), 2) AS timing_share_pct,
    SUM(CASE WHEN activity_group = '第一阶段活跃' THEN 1 ELSE 0 END) AS phase1_active_apply_events,
    ROUND(SUM(CASE WHEN activity_group = '第一阶段活跃' THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 2) AS phase1_active_share_pct,
    SUM(CASE WHEN activity_group = '第二阶段新增活跃' THEN 1 ELSE 0 END) AS phase2_new_active_apply_events,
    ROUND(SUM(CASE WHEN activity_group = '第二阶段新增活跃' THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 2) AS phase2_new_active_share_pct
FROM bucketed
GROUP BY cohort, timing_bucket, bucket_order

UNION ALL

SELECT
    cohort,
    '总计' AS timing_bucket,
    COUNT(*),
    100.00,
    SUM(CASE WHEN activity_group = '第一阶段活跃' THEN 1 ELSE 0 END),
    ROUND(SUM(CASE WHEN activity_group = '第一阶段活跃' THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 2),
    SUM(CASE WHEN activity_group = '第二阶段新增活跃' THEN 1 ELSE 0 END),
    ROUND(SUM(CASE WHEN activity_group = '第二阶段新增活跃' THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 2)
FROM bucketed
GROUP BY cohort
ORDER BY cohort, timing_bucket;

数据说明：第二阶段新增活跃指第一阶段内没有 event_track.active_date、但在第二阶段完成首次提单的用户；提单本身意味着其在第二阶段进入 App。此定义不用于判断第一阶段活跃。
